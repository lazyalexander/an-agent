# 宿主 CLI 接受

[English](../../../../../../crates/an-agent-host/tests/cli/README.md) · 中文译文，以英文为准。 · [中文目录](../../../../README.md)

构建所选宿主的二进制文件，然后传递其明确的路径。没有运行器会构建二进制文件、读取模型凭证或调用 Loom。Python 3 标准库即可满足需求。平台兼容性集中体现在 `host_qualification.py`；详见 [支持和资格矩阵](../../../../doc/platforms.md)。此前提条件不替代每个案例中执行的宿主强制约束。

```sh
cargo build --locked -p an-agent-host --bin an-agent-host
python3 crates/an-agent-host/tests/cli/native_state.py \
  --host target/debug/an-agent-host --evidence /private/tmp/native-state-evidence
```

`native_state.py` 需要符合资格的原生工作区后端；其他平台报告跳过，而非成功运行时的资格验证。它测试显式初始化、固定状态输入、成功接受输出提交、过时冲突、取消候选拒绝、中断 HEAD 发布、孤儿拒绝、可重复提交确认、擦除擦除和一个从固定检查点显式启动的新实例。计数器规则属于此固定，而非宿主。

Round-control 情景也通过显式暂停/恢复、绑定检查点的暂停、过时批准/提案、丢失 HEAD 防护、中断控制发布、更改-kit/状态拒绝、独立的第二个实例和暂停时的擦除回收，来通过验证。活体执行和未知开始证据拒绝控制；活体测试要求在开始前确认取消。安全点是一个已完成、正式接受的轮次，而非正在进行的信号。

可选 `--legacy-host /path/to/pre-control/an-agent-host` 验证一个较旧的宿主在激活前读取遗留实例，并在暂停和恢复后拒绝升级实例。每个选中的二进制文件应单独构建并使用稳定副本；在外部套件调用期间，不得重建共享可执行文件。

存储覆盖使用一个真实 16 MiB 选定输入，验证逻辑快照删除与不变的正式产物/状态，暂停后继续执行，并将固定报告输入到另一个实例中。未知条目/更改输入和丢失收集凭证不能授权新删除。一个上升的操作者头寸请求会行使真实无_spawn拒绝路径，而不填充磁盘。

`native_release.py --host HOST --evidence NEW_DIRECTORY` 使用真实资格的原生执行来通过验证读取只读发布比较、相同标签的更改内容、不支持的能力/依赖拒绝、分离实例/状态初始化、过时批准拒绝、失败候选输出拒绝和原始实例延续。它不添加任何内置更新器或自动迁移。宿主拥有此失败矩阵；Loom 单独测试其实际导出修订。

`native_events.py --host HOST --evidence NEW_DIRECTORY` 通过真实 v3 艺术品事件发布、分离订阅/启动批准、固定旧版本输入、显式接受输出消费、重复交付、缺失确认、过时/撤销/外国身份、并发观察、实际取消和丢失面证据来通过验证。缺失记录情况故意在已知执行后删除记录；它们不声称任意过程崩溃或电源损失恢复。它也通过显式状态无状态成功参考发布、保留的对等方、缺失结果/确认/释放凭证、部分状态初始化和不支持隔离请求来通过验证。状态有状态成功声明保持保留于 `native_data_state.py`；无负载删除未被通过。

没有模型、背景分发或 GUI 被使用。配对的 Loom _SUITE 拥有实际档案/导出手交；此宿主_SUITE 拥有拒绝/故障矩阵。

`native_binary.py` 使用相同的 `--host` 和 `--evidence` 参数。它通过 Python/二进制合同、依赖变化在启动前和接受前、只读运行时根、固定字节事件消费、实际取消和选定运行时消失后保留的产品来通过验证。仅 Python 标准库由此宿主拥有的拒绝套件所需。分离的 Loom 文档套件安装其示例依赖并验证可编辑的 XLSX/PPTX。

`native_data_state.py` 使用相同的 --host/--evidence 参数。它通过直接和事件启动来分别处理固定业务/检查点输入，包括在scratch收集后出现的过时提交、未知交付的围栏以及状态变更拒绝。真实取消在终止确认前拒绝收集，然后在收集私有文件时保留正式数据/状态/产品。一个新启动的Python实例显式从保留的状态中启动，验证了第二个合格的运行时。业务算术是一个测试用例。

每个命令都有一个有限的等待时间，并记录stdout/stderr以及它的退出状态。在客户端截止时间，运行器请求宿主取消；未知终止会失败测试用例并保留证据。它从不自动重跑一个执行。所有fixture目录、凭证和命令观察结果都被保留，包括在失败时。操作性证据包含本地路径；不要直接发布原始内容。

`native_input_references.py --host HOST --fixture COMPLETED_DATA_STATE_DIRECTORY
--evidence NEW_DIRECTORY` 消耗一个新鲜成功的 `native_data_state.py` 案例。它检查成功的所有者引用，启动并取消一个独立的实时消费者，并在确认工作和快照收集后释放。它检查未知结算、错误批准、另一个保留的消费者、不变的负载哈希值和缺少释放确认。一个注入的第二个分类锁证明部分注册无法执行或静默重新获取。在持有生产者/分类锁的情况下，检查生产者侧的可选参考视图，而一个真实消费者运行。它区分源标记和消费者完成，包含部分注册，并拒绝无效的源记录。这些故障探针是故意拒绝检查，而不是生产重试策略。fixture的生产者在案例中被退休；不要将其用于另一个运行。这覆盖了新的管理输入，而不是一个完整的PIN普查或正式产品GC。

事件用例也能够验证读取只读交付库存和实际执行期间的前台监控，包括证据变化、观察取消、截止时间退出和重启而不重播未知工作。监控器输出NDJSON，而普通宿主命令返回一个JSON值。

`native_dispatch.py --host HOST --evidence NEW_DIRECTORY` 能够验证有限批准的状态机头端交付。它覆盖精确输入、无隐式状态链、过时提交、排水停止与取消、确认仅清理、实际交付日志写入失败和中断观察而不重播。

交付用例也能够验证订阅准入暂停/恢复、旧直接和批量批准拒绝、运行工作托管和恢复后无重播。可选地传递`--legacy-host OLD_HOST`以调用一个先前的v1仅二进制并验证升级拒绝。其摘要区分该额外检查是否运行。

交付用例也丢失了一个已知完成的摘要，检查惰性/错误批准和缺失条目拒绝，显式重建它并检查不变的尝试次数。部分停止的批次无法使用该重建路径。

`native_route_successor.py --host HOST --evidence NEW_DIRECTORY` 运行实际的旧和新状态机接收器，包括在旧工作运行时的平滑过渡，历史和不确定事件拒绝，更改批准拒绝，显式状态转移和保留托管。`--legacy-host OLD_HOST` 可选地验证旧宿主拒绝；可移植摘要记录是否运行以及选择的二进制哈希。

`native_capacity.py --host HOST --evidence NEW_DIRECTORY` 通过两个真实无头实例，四次执行8 MiB的轮询。测量生产者逻辑字节数在前后有限私有集合中的变化，并验证并发消费者进度、取消、保留的产品/状态/外部输入以及丢失凭证的拒绝。它报告没有物理APFS节省或正式产品GC保证。

`native_retirement.py --host HOST --evidence NEW_DIRECTORY` 在一个真实有状态接收者运行时，退休一个已已验收的输出。拒绝另一个接收者的过时直接/事件/批次批准，并在关闭后完成接受、状态提交和因果确认。它检查无关/新版本、私有集合、已确认的取消、保留的字节以及撕裂的退休记录，不重试。这符合准入关闭，而非正式数据删除或独立副本的撤销。单元测试自身并发读取和标记故障检查。

`native_monitor.py` 消耗一个刚完成的`native_events.py`测试用例，并创建独立测量的工作空间。添加六个真实生产者轮询，然后在0/1/4观察者下运行144个唯一撤销，无重试。每次使用新鲜的测试用例；失败/未知场景必须不重用相同的轮询ID。它记录每条命令、观察者结果和自愿时间，并拒绝观察写入、控制拒绝或观察者失败。它不削弱前一个真实事件套件中所涉及的过期批准、取消或回收断言。

`native_sessions.py --host HOST --evidence NEW_DIRECTORY` 通过真实固定输入/状态消费者，使用真实 pinned-input/state 消费者，验证会话拥有的有限线程。显式批准在执行上重叠；取消影响一个会话，暂停消耗，过期请求失败，关闭保留产品和丢失完成凭证防止关闭/重放。同时同工作空间准入仍为fail-fast，而非排队或重试。

`native_material_boundary.py --host HOST --evidence NEW_DIRECTORY` 启动两个真实原生spools。提供作为普通输入的路径不会授予另一实例的输出/身份或工作区事件日志的访问权限：内容读写必须失败。私有指令说明保持为scratch，创建无交付，并被排除在已接受产品之外。元数据可见性被测量，而非声称秘密。没有模型运行；此不满足上下文摄入、通用请求/回复IPC或调度器公平性。请参见运行时接受矩阵在[会话合同](../../../../doc/session-and-retention.md)中。

`native_peer.py --host HOST --evidence NEW_DIRECTORY` 通过实际原生spools执行分阶段请求/回复/延续。等待创建无进程或持有实例锁；独立发送者作业可重叠接收者执行。检查固定输入/回复钉钉、过期生成、错误关联、取消、缺少完成无重放和确认仅收集。撤销关闭未来交付，而接收者监督者拥有终止。这不是实时IPC，公平性基准或后台调度器。

`native_supervisor_loss.py --host HOST --evidence NEW_DIRECTORY`对比
SIGTERM与SIGKILL对实际启动的CLI进行区分。两个有限工作者在原始截止时间后使孤儿执行可观察。它检查原始组结算是否已处理取消，保守托管在所有者丢失后，独立实例进度和保留的正式产品。可丢弃的测试用具在采样过程退出后移除过时的锁标记，以验证缺失终止证据独立阻止接受、收集、卸载和重放。该注入是一个测试操作，而非恢复配方。其总结区分通过拒绝检查的通过与观察到的缺失调用无关监督者。本地进程样本不具有清理权限。

`native_supervisor.py`和`native_supervisor_state.py`取`--host HOST
--evidence NEW_DIRECTORY`。它们符合文件输入和固定检查点监督：客户端退出、持续超时/取消、监督者丢失、无重放和仅确认收集。状态套件在选择旧版本前先推进HEAD，并验证保留的检查点；`--combined`也固定业务数据并拒绝更改选择器。PID仅用于故障注入和观察；接受的产品和独立实例不受影响。

`native_harness_adapter.py --host HOST --evidence NEW_DIRECTORY` 使用两个后台协议
任务验收补充指令、事件游标、同级与旧句柄拒绝、命令去重、回执丢失保留、独立取消
及守护服务重启后的原进程身份。真实模型链使用 `document_activity.py --app-server`。
