# memstream

[English](../../../../../../crates/an-agent-core/src/memstream/README.md) · 中文译文，以英文为准。 · [中文目录](../../../../README.md)

磁带：只追加的 JSONL 事件日志，系统唯一的真相来源。热路径是 `context clips`；观察/重放数据是冷数据 —— 索引、嵌入和图视图是其他地方构建的投影，绝不会是源。

**准入规则：** 事件模型、存储和验证。无投影，无查询引擎。

**依赖项：** `det_seam`；目前也依赖 `act`（信封和效果类型）—— 请参见下文。

**不变量：** 只追加，从不重写（一个例外：崩溃撕裂的尾部隔离 —— 请参见持久性）；读者容忍模式漂移（serde 默认值 + `skip_serializing_if`）；`validate()`在写入时；新语义 = 新字段或类型。

**持久性：** 一个写入锁覆盖序列保留、一个单一的 `write` 和 `fsync`；只有在持久写入之后 `seq` 才会前进。损坏的字节永远不会作为事件提供：一个崩溃撕裂的最后行会被隔离到 `<tape>.corrupt`（证据保留）并截断 —— 唯一允许的重写；其他地方的损坏会导致整个存储失败。

**已知的结构债务：** `act` 和 `memstream` 相互导入（作为模块，块分割它们为 crate 是可以的）。修复方向：将信封类型下沉到磁带之下，或让 `ActOnEvent` 携带通用负载。一个未来的切片。

写入者所有权在存储 drop 时通过显式解锁结束。仅关闭文件是不够的，当一个并发分叉的子进程在 exec 之前仍持有继承的打开文件描述符时。继承的描述符不是独立的写入者授权；新的存储必须获取自己的锁。宿主回归保持这样的子进程存活，当父进程 drop 并立即重新获取磁带时。

一个存储绑定到打开它的 PID。在 `fork` 之后，继承的存储方法在获取互斥锁、保留序列、读取或修复磁带，或访问工具负载之前会拒绝并返回 `InheritedProcess`。子进程销毁时会关闭其继承的描述符，而不会解锁父进程的打开文件描述符。父进程销毁时仍会显式解锁，因此即使一个不活跃的继承描述符仍保持打开，新的写入者仍可以获取所有权。子进程必须打开一个新的存储并获取自己的写入锁才能使用磁带；继承的对象永远不会仅仅因为原始拥有者退出而变得有效。

回归覆盖包括子进程侧的销毁，而父进程仍保留所有权，新写入者接管后过时的继承读取/追加/负载调用，拒绝修复由该写入者拥有的撕裂尾部，以及在锁定状态互斥锁之前进行的所有者检查。PID 检查是一个对象生命周期规则，而不是沙箱或对多线程分叉后任意应用程序代码的保证。独立的只读负载解析器不拥有磁带，也不执行修复。
