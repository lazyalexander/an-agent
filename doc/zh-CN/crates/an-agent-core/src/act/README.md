# act

[English](../../../../../../crates/an-agent-core/src/act/README.md) · 中文译文，以英文为准。 · [中文目录](../../../../README.md)

准入：每一个有成效的操作都必须经过这里。意图在执行前被记录，效果在执行后被记录。一个操作携带一个许可。效果是从工具标签中投射出来的。一个生成的章程是一个独立的天花板（工具标签加上信号），并且不会存储在操作中。

**准入规则：** 权限词汇（`Permit`, `ToolTag`, `Charter`）、信封、操作包装（`run_tool_act`）以及作用域工具注册表（`ToolRegistry` — 空间准入：哪些工具存在，RAII注销）。没有工具实现，也没有模型代码 —— 这些都是该层封装的出调用。

**授权语义：** `Deny` 阻塞；公共的 `run_tool_act` 在执行前拒绝 `Ask`。只有受信任的控制边界才能消费一个绑定监督者的单次批准并进入经过审查的 Ask 路径。批准不会扩大卡片的文件或内存面。文件路径仍然记录在作用域中，而不是操作系统沙箱的强制执行。

**词汇规则：** `ActKind` 仅限于意图领域（陈述、调用、记住、……）。通道通过 `ActEnvelope.tool` 运行：`Some(name)` = 通过工具，`None` = 模型侧或直接。通用工具调用和模型调用共享 `invoke`。

**依赖项：** `memstream`（用于记录）。资源助记符存在于该模块中。永远不要使用 `principal`、`an-agent-spool`，以及工作区 CAS 存储。

**工具负载边界：** 新的工具操作、观察和记住片段携带 `tool_payload_v1` 引用（SHA-256 和字节长度），而不是参数/结果主体。主体存在于会话的私有 `blobs/` 目录中；读者验证身份并保留旧的内联兼容性。工具名称和调用 ID 限制为 256 字节，参数/结果限制为 1 MiB。超大调用在记录、快照存储或执行前失败；超大的结果会留下一个拒绝观察并返回错误，因为效果可能已经发生。这是准入/存储边界，而不是工具内部分配内存的限制。活跃的有界工具消息仍然包含结果。
 blobs 和派生上下文是敏感的；此更改不会删除历史内联日志或删除私有存储。磁带备份需要其引用的 blobs。

显式选择的片段必须在模型请求被记录或发送前成功解析。缺失或损坏的主体会拒绝调用；不可用的标记只是历史预览。派生工具上下文包括事件信封中的工具名称，而原始负载 API 仍然仅返回主体。上下文组装和剪裁在不将主体内联回磁带的情况下保留此身份。
