# an-agent-core

[English](../../../../crates/an-agent-core/README.md) · 中文译文，以英文为准。 · [中文目录](../../README.md)

内核。Spool 构造器位于 `an-agent-spool`。嵌入者向 `build_with` / `spawn_with` 显式提供工具构造器；编码框架拥有其外壳工具、会话上下文和压缩。CAS 存储位于 `an-agent-workspace`。记录器工作区（`Wp`）也在此处。

## 模块

| 模块 | 角色 |
|---|---|
| `memstream` | 磁带。[单写者所有权和恢复](../../doc/core-contracts.md)。只追加 JSONL；事件包含类型、引用（因果边）、动作信封和生成卡片的哈希。读者吸收模式漂移（serde 默认值 + `skip_serializing_if`）；历史记录永远不会被重写。 |
| `act` | 入口。意图在执行前被记录在磁带上，效果在执行后。一个动作包含 `permit` 和从工具标签中投影的效果。一个生成 `Charter`（工具标签加信号）是一个上限，而不是动作字段。资源助记符在此处。`ActKind` 是意图域词汇表；通道（工具 vs 模型）在 `ActEnvelope.tool` 上运行。 |
| `principal` | 代理身份。一个 `AgentCard` = 模型规范 + 提示 + 工具授权 + 内核引用 — 不可变、内容寻址、通过超越版本化，永不被修改。卡片不保存任何记忆和任何密钥。`factory::build_with` 获取调用者的工具构造器；此 crate 不注册任何构造器。 |
| `agent` | 一个活跃卡片及其私有目录和磁带。`spawn_with` 将它们绑定。工厂产品是一个 `BuiltAgent`。 |
| `control` | 与 [交付时效性和落地证据](../../doc/core-contracts.md) 相关的宿主接口。通过 `open_agent` 打开代理，推进、取消、完成、发送并运行授权工具。将独立的 `an-agent-supervision` 状态机适配到受信任的主体、权限上限和磁带证据。响应从不自动安排工作。 |
| `seat` | 谁被挂载，以及可能运行的一个周期。由宿主接口和记录器共享。 |
| `recorder` | 文件工作区管理员：`Wp`、子工作区日志和投影恢复。不是宿主接口。 |
| `workspace` | 宿主的 `WorkspaceLedger` 事件、精确的配置快照和 [验证的环境生成](../../doc/core-contracts.md)。不是 `Wp`，也不是 CAS crate。 |
| `det_seam` | 确定性接口 — 唯一允许接触操作系统时间和熵的地方。由 `clippy.toml` 禁止的方法强制执行，而不是由审查员的警觉性。 |

## 不变性（审查应监督的内容）

1. 磁带是只追加的。新语义以新字段或新类型出现；旧行必须保持可读。
2. 模型调用和工具调用都是 `invoke` 动作；磁带记录的是薄痕迹（哈希、令牌使用），而不是完整负载。
3. 工具是无认知的效果器。任何包含 LLM 调用的内容都是一个代理，通过委托访问 — 而不是工具。
4. 内核从不依赖 `tests/` 或组合 crate。
5. 操作系统时间/熵只能在 `det_seam` 之外； `unwrap`/`expect` 不能在测试之外。

## 习惯用法

交付和模型入口保留带有角色标签的合同投影、显式的边界覆盖和阴影比较诊断，它们在现有的语义审计记录中。独立检查器不控制执行；硬闸、审查路由和生命周期执行保持不变。缺失或未覆盖的输入会以未知形式可见，而不是表示为安全的证明。

`AgentControl::run` 也保留 `tool_contract` 审计观察，用于绑定工具授权和精确审查闸。批准资格记录了子 Ask 授权、主管 Go 授权和现有章程/文件接口上限。这些投影是诊断性的，而不是文件系统执行或新的批准令牌。必需的审计失败会阻止执行；一个已经消耗的批准将保持消耗。独立检查器从不重试或安排操作。

模型边界在调用准入和终端发布时也会检查依赖项的有效性。注册、配置/环境生成以及实时审核范围必须保持最新；显式剪辑会固定历史记录。过时或未知的结果仅限审计，并会触发调度审核，或在原始范围已弃用时触发宿主错误。收据仍会说明实际的调用结果。这并非宿主文档事务隔离或自动回滚。

描述的挂载项携带一个 `SpoolDescriptor`：一个稳定的包符号和由可信加载器提供的精确YAML快照。包不是挂载别名或实例ID。核心会为挂载的整个生命周期保留一份副本；描述符变更需要新的挂载，且不会继承其前者的审核。交付和模型证据引用包和保留的描述符字节。这些是来自加载器的声明，而非原生代码身份的证明。直接的旧版挂载方法仍然可用，无需发明描述符证据。

一个文件夹 = 一个proto-package：每个模块目录都携带一个简薄的README（用途、准入规则、依赖方向）。仅规则级别的文本 —— 实现细节会随时间变化。

遵循仓库级别的规范：`cargo check → clippy → test`，编译前进行批量编辑，不要使用 `cargo clean`。依赖项集中于工作区根目录；添加任何内容都必须有理由。
