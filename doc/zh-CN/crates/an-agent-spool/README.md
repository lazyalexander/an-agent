# an-agent-spool

[English](../../../../crates/an-agent-spool/README.md) · 中文译文，以英文为准。 · [中文目录](../../README.md)

内部能力，被卷绕在滚筒上。此crate不依赖于该 crate。

**词汇规范：** 一个 *spool* 是一个内部能力 — 它从不直接接触外部世界。外部编码客户端使用宿主的有限MCP工具。可信嵌入式工具需要显式调用者提供的构造函数；内核不注册任何内置shell。

**该文档是一个授权信封，而非自我描述。** 一个spool回答四个问题：代码如何运行（`constructor`），它能触及的最坏情况（`effect`天花板），必须存在的内容（`requires`），如何回溯它（`inverse`），以及它所配置的环境（`config`）。一个spool在运行时形成的系统并非声明 — 它是通过磁带上的mount/unmount操作和注册来观察的。该文档存在于注册表中；已挂载的实例是它的化身。

**三个层面的规范：**

1. **之前（准入）：** 静态折叠覆盖已锁定的需要闭包 — 效果天花板合并（一个spool产生一个网络出口成员，具有出口可达性），可逆性与AND（一个不可逆成员使mount不可逆），信任楼层在最弱的成员上。可判定因为闭包是展开的且精确锁定；发布顺序是拓扑顺序，因此闭包是无环的。
2. **期间（生命周期）：** 空间存在是内核的RAII注册；被丢弃的守护程序取消注册。
3. **之后（磁带 + 反向）：** 磁带是结算 — 一个声明是预算，磁带是审计；两者之间的偏差是审查所关注的。`inverse`命名回滚；目前尚未有任何东西消费它。

**声明不是证明。** YAML可以手写，因此静态检查限制了准入允许的内容，但无法证明行为与声明匹配。诚实的链：声明设定预算 → 构造拒绝面对构造函数，无法连线 → rhai天花板由宿主-fn wiring物理强制执行，宿主天花板基于审查（因此信任楼层），磁带将声明与行为相抵消。

**注册表：** 仅追加，内容地址化。一个发布体（`blobs/<sha256>` + `index.jsonl`）永远不会被重写；一个后续版本是一个新体，因此旧工作区写入可以恢复生成该体的描述符。

**挂载身份：** 宿主将现有的YAML `name` 作为稳定包符号并保留每个挂载的精确YAML字节。实例别名和生命周期ID保持独立。其他合同字段保持在YAML中。这添加了没有版本范围、依赖解析器、二进制认证或热更新系统；现有的注册表版本字段保持不变以确保兼容性。

**依赖项：** `an-agent-core`（`Tool`，facet词汇）。从不：`memstream`直接，`principal`。

## 执行边界术语

一个spool释放携带核心领域 **silks** 和可能包含 **kit** 胶水。Silks在尝试期间是只读的；kit编辑使用独立可编辑的工作副本。见[代码契约](../../doc/spool-code.md)；这不是一个新的解析器或运行时保证。其执行尝试是宿主/后端的所有权和生命周期单元。该解析器和现有的嵌入式体API不创建该边界：一个在进程中的`SpoolBeat`是可信嵌入代码，而不是隔离的工作负载。见[实现审计和迁移](../../doc/architecture.md)。历史silk协议记录和当前profile/event令牌保持兼容性身份；它们不是可执行的silk声明。

## 注册表发布和恢复

`Registry` 对依赖检查、不可变名称/版本检查和索引提交进行序列化，同时在追加只读索引文件上设置操作系统 advisory 锁。独立打开的实例和协作的本地进程使用相同的锁；公开的读取也使用该锁，因此它们不会解释写入者的部分追加。该过程重用了标准库文件锁机制，引入了没有锁文件租约或过期锁的删除。注册表路径和索引 inode 必须由操作员所有；这并非防止恶意替换或分布式/网络文件系统锁契约的保护。

Blob 暂存使用唯一、仅创建一次的文件。在重命名前同步字节，Unix 系统中 blob 目录同步，发布前同步索引。失败的追加/同步会导致不确定的发布，而非回滚。完整的条目可 idempotently 恢复；不完整的尾部、冲突的历史名称/版本哈希或不匹配的 blob 识别信息将被拒绝进行检查。注册表从不静默截断历史或选择第一个冲突的条目。未索引的 blob 或崩溃时的暂存垃圾不会自动回收。与磁带修复不同，注册表历史没有自动尾部修复策略。

## 递归撤回

移除范围首先计划现有的最新子节点顺序，并模拟整个子树的包装器移除。如果 pinned 父节点、pinned 子节点或不兼容的兄弟包装器顺序被拒绝，那么在任何可销毁的运行之前都不会执行计划。在目标之前安排的内部包装器是允许的；这并非对包装子树的全面禁令。成功移除会保留原有的子节点报告和逆注册处置顺序。`update` 使用相同的预检。

计划存在于 `scope/unmount.rs`；实时效果撤回仍存在于 `ScopeTree`。实时 pin 检查在执行期间仍保持防御性。用户提供的可销毁对象被信任为逆向：在逆向过程中，任意拓扑修改、递归或恐慌不会被事务化，仍可能产生部分效果。此更改防止可预测的拓扑失败，而非任意回调回滚。
