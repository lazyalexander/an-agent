# 实现状态和下一步计划

[English](../../status.md) · 中文译文，以英文为准。 · [中文目录](../README.md)

此页面将合格的本地合同与架构的总体意图区分开。成功的示例不会扩展运行时的授权。已审查的无头执行是当前的产品范围；平台特定的覆盖和延迟目标仍保留在[支持和资格矩阵](platforms.md)中。

## P0：受限无头事件交付

P0已通过审查的本地CLI spools资格，不适用于任意不受信任的代理：

- 不可变的发布/实例绑定，两个内部silk步骤，限定的kit编辑，独立的实例，整体组取消和基准恢复。
- 明确的v3工作空间产物事实，固定订阅，分开的交付批准，接受输出保管和因果消费确认。
- 一个固定业务输入与一个明确选择的不可见已提交检查点结合；无效状态冲突拒绝和确认取消保留。
- 明确的每尝试监督文件、检查点和组合数据/状态启动，这些在客户端丢失时仍存活。原生CLI事件交付和两个对等阶段使用相同的尝试所有者。有限控制器管理每个批准的批次或线程。确认预启动取消可以关闭一轮而无需授予保管权。
- 明确的完整原始执行/验收证据的完全一致性校验。缺失终止或不确定执行永远不会授权重跑。
- 可选的由操作员选择的Python环境和声明的二进制产品；配对文档示例演练保存的XLSX和固定下游PPTX。

见[原生spool](native-spool.md)、[原生事件](native-events.md)、[原生状态](native-state.md)和[Python/二进制输入](native-spool.md)。

## P1：日常本地事件操作

| 能力 | 限定边界 |
| --- | --- |
| 库存和监控 | 仅读取的待处理库存和有限的前台变化监控；无执行权限 |
| 有限分发 | 1..16个明确批准的选型，每个条目固定状态，排水停止/取消和一个独占无恢复边界；保管权保持明确 |
| 订阅控制 | 生成绑定暂停/恢复和永久撤销；已接受的保管权延续 |
| 接收者继承 | 不可变的继承者和固定事件切分；无历史重放，自动状态迁移或旧工作回退 |
| 完成总结修复 | 从每个原始条目/开始/交付显式重建，并确认成功接收；无执行或部分批次恢复 |
| 私有容量维护 | 通过原始所有权/结算门显式有限收集工作/快照；四轮真实8 MiB和消费者进度资格 |
| 产物输入退休 | 一个接受输出可关闭新修订基于的获取；已接受工作、独立检查点、原始字节和因果证据保留 |
| 原生输入所有权 | 精确管理的主张；私有收集后显式取消所有者或承认无状态成功释放；显式不可变检查点桩；批准完全覆盖输入后发布状态事件；不确定所有者保留；退休审查检查显式选择的消费者凭证；遗留读者普查仍不完整 |
| 注册发布 | 新 `--registered` 接受记录，原生输入尝试，显式复制读者和检查点桩从首次发布。显式精确版本收集需要关闭并验证读者释放。遗留目录保留。见[原生存储](../../native-storage.md#registered-copies-and-explicit-payload-deletion)。 | /no_check

本地头节点P1路径在三个生产轮次和两个消费者之间已通过验证。一个固定事件在新版本存在后喂养两个消费者。一个状态化的消费者在其对等节点活跃时提交，生产者可以在确认取消后收集已释放的版本。一个新的客户端可以在提交的CLI退出后取消。失去尝试所有者会留下一个持有执行。配对资格记录了磁盘使用和确切的字节数。已注册的检查点现在可以关闭准入并明确释放自己的锁。遗留的读者历史记录其锁。参见[检查点退休](../../native-state.md#explicit-checkpoint-retirement)。

路由监督套件也分别验证了客户端、控制器和尝试所有者丢失。参见[执行所有权](../../session-and-retention.md#routed-execution-ownership)。

原生队列控制有限选择。一个对等节点可以接收一个固定、已接受的文本修订版本的已检查上下文包。核心代理的对话记录保持私有。参见[受限分发和身份契约](../../session-and-retention.md#bounded-peer-context)以了解支持的来源和披露限制。

## 延迟作用域和现有表面

| 表面 | 当前作用域或推迟原因 |
| --- | --- |
| 核心/嵌入式代理 | 已经存在的事件/磁带/准入/监督；在进程中的主体保持信任的嵌入代码 |
| 原生注册的配置文件 | 基于哈希的stdio/文件部署和平台特定的执行约束；不支持任意恶意代理的隔离 |
| 可选OpenShell | 已通过资格的单程序执行和终止/身份校验；本阶段不包含新的虚拟机后端 |
| 审核工作区作业 | 管理员选择的工作流程和二进制所有权；不构成通用生产spool ABI |
| 意义 | 纯粹的声明/评估和现有适配器；不构成全面静态分析或安全边界 |
| Weaver | 可选的Loom侧审查工作流；宿主契约提案槽位不是宿主拥有的代理循环 |
| 编程套件内部 | 原生客户端拥有shell工具、会话组装和压缩。未使用的上下文/工厂crate和通用ReAct策略已退役；有限MCP、显式上下文披露和监督宿主执行仍被支持。参见[harness所有权](../../model-services.md#native-harness-ownership)。 |
| 状态/释放迁移 | 显式新鲜实例检查点播种和只读释放比较；没有自动线性、域合并或就地迁移 |
| 生效暂停 | 允许准入暂停和检查点/停止暂停；进程内存/VM恢复和飞行中安全点信号不被支持 |
| 额外编排 | 多个业务输入、生产者/拓扑编辑、后台准入和低延迟通道等待具体需求 |
| GPU/GUI和恶意套件 | 需要独立平台、应用程序和执行约束资格 |

Spool交互仍保持工作区事件路由。领域分支、循环和子代理决策保持在silk/kit。未来高频通道需要单独授权；它不是将宿主转换为业务图引擎的理由。

Loom拥有作者、检查、打包和窄配对兼容性证据。一个代理拥有运行时权威、监督、状态/制品所有权和保留。没有反向运行依赖。保留现有CLI/配置文件/磁带身份和旧发布字节；不支持的执行拒绝而非回退。开发合并需要差分审查、真实接受和每个CI门，随后由用户通知。主要推广仍由用户触发。
