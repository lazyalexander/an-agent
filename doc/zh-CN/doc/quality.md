# 仓库架构门禁

[English](../../quality.md) · 中文译文，以英文为准。 · [中文目录](../README.md)

在打开 PR 之前运行 `cargo arch`。它会与 `origin/dev-advance` 进行比较；
使用 `cargo arch --base COMMIT` 来指定一个显式获取的目标提交。它永远不会
重写基线。CI 在现有的原生宿主检查中运行相同的命令，使用 PR 的基 SHA（或上一次推送的 SHA），而不是一个变动的分支。

## 所有权

- `ARCHITECTURE.toml`：与 SPACE 兼容的大小、命令提及和命名规则。
- `architecture-baseline.toml`：现有的例外情况和精确的大写。
- `architecture-policy.toml`：本地建议阈值和依赖关系。
- `documentation-policy.toml`：中心页面和长度预算。
- `tools/archcheck`：薄的失败关闭包装器；一个独立的 Cargo 工作区
  和锁定文件，没有产品依赖或运行时耦合。

SPACE 检查器是一个 git 依赖项，固定到提交
`57c7c0c47a73373a974c5b542d180599795465da`，包
`pplx-space-archcheck`，上游 Apache-2.0，版权属于 Perplexity AI。
源代码和上游许可证仍保留在该依赖项中；没有检查器源代码被复制到此仓库。产品锁定文件保持不变。初始工具设置需要访问 GitHub 和 crates.io；后续运行使用锁定缓存。
参见 [上游](https://github.com/perplexityai/SPACE/tree/57c7c0c47a73373a974c5b542d180599795465da/crates/tools/archcheck)。

## 以测量规则而非审美评分

生产文件有一个 500 行的有效行数上限和一个 350 行的建议值。
上游的度量标准排除了空行和开头的 `//` 注释；块注释、属性和内联测试模块会被计算。上游库存排除了单独的测试文件；
包装器报告 600 行的警告和一个 800 行的 **建议**，而不是测试删除的激励。此初始切片不强制执行函数长度或解析 Rust 以进行类型解析的进程调用。

命令构造提及仅限于显式命名的宿主所有权边界。现有的文件任务实例数量受到限制，而非声明为安全。平台适配器和进程所有者仍然是合法的命令构造者。
正则表达式是一个审查 lint：别名、宏或间接调用可以规避它；字符串和内联测试可以计数。它不会强制执行沙箱权限，也不能证明命令会经过监督者。运行时控制和审查仍然是必要的。我们不对所有 CLI 调用施加一个全局配额。

依赖检查使用 Cargo 声明的非开发依赖项，包括目标和可选声明，沿着工作区包路径进行检查。它们检查实际的包名称，而非别名。外部依赖项的内部结构不会被展开。运行时工作区包不得依赖 Waver 或此检查器；核心不得依赖宿主或所选的 HTTP 客户端。不会推断出对所有 Tokio 特性或所有文件系统操作的全面禁用。

## 螺丝刀和政策变更

现有的大文件可能仍然存在，但不能超过其列出的上限。新的大文件、新的命令站点超出审查边界、提高的上限、新的例外和过时的条目将失败。当债务减少时，降低或删除条目。
Git 重命名证据将传递给上游引擎；移动文件不被视为新的例外。不提供自动基线重置。

缺少或格式错误的当前/基础配置、未知的配置键、不可用的 Git 基础、元数据失败和跳过的比较将失败关闭。只有精确的最后一次政策提交
`f54cfa71e463a7b2902a16a26494dc44fce2485a` 可以启动初始审查基线。此锚点在代码和 TOML 中都会被检查。它不是一种通用的“缺少基线意味着通过”的路径。

第一次稳定线推广包含一个单独评审的迁移：当基础是正好 pre-gate main `a3ff193c7d9732f2c272125e9b9c925bc9096567` 时，与在原始 gate 实现中提交的规则和基线 `8c89829b9de7506925a5d1d107d04df500ddd54f` 进行比较。该策略提交必须存在于 HEAD 的祖先中。gate 仍然检查当前树、策略一致性、新增条目、提升的上限和过期条目；重命名检测仍使用实际的 PR 基础。它不会复制当前基线或禁用任何发现。没有分支名称、其他旧提交、缺失文件或格式错误的策略会触发此迁移。一旦 main 承载了 gate，普通的 base-to-head 比较将再次适用。

对规则文件的语义更改将无法与目标提交进行比较。因此，有意的策略迁移需要自己的明确评审更改到 gate，而不是普通功能 PR 的新豁免。注释可能会更改，但不会更改策略。检查器、lockfile、Cargo 别名、CI 和策略文件是评审敏感的；CODEOWNERS 请求所有者评审。CODEOWNERS 单独不能启用服务器端的必填评审。现有的必填原生宿主检查现在包括 gate；不会引入分支保护绕过。

## 重构纪律

按权威、状态所有权和责任进行拆分，而不是任意的行边界。保持取消/接受决策可读为一个状态机。不要扩展公共 API 或引入 catch-all 帮助库来满足一个上限。保留注释和测试；结构移动和行为更改应放在不同的提交中。每个拆分仍然运行 workspace 测试、clippy 和格式化。

工具检查：

```sh
cargo test --manifest-path tools/archcheck/Cargo.toml --locked
cargo clippy --manifest-path tools/archcheck/Cargo.toml --all-targets --locked -- -D warnings
cargo fmt --manifest-path tools/archcheck/Cargo.toml -- --check
cargo arch
```

工具测试故意破坏基线，添加禁止命令提及，增大文件体积，提高限制并削弱策略。仅仅通过当前树的测试并不能证明门禁机制有效。

## 文档门禁

`documentation-policy.toml` 拥有文档预算。`cargo arch` 检查跟踪且未被忽略的候选 Markdown 文件，因此新页面无需被暂存即可被检查。叙述性文档应放在 `doc/`；只有 README 文件和根目录贡献者说明文件应与代码并存。它限制中心页面数量、单个页面长度和 README 长度，并拒绝缺少本地文件链接的情况。指向私有或被忽略材料的链接不被视为已发布的文档。外部 URL 和标题片段不会被此检查获取或验证。

简化中文镜像位于 `doc/zh-CN/`，需要一个规范的英文页面，并继承其行数限制和链接检查。每个主题仅计算一次。`AGENTS.md` 的中文副本命名为 `AGENTS.zh-CN.md` 作为参考；英文版本具有优先权。

不要仅为了满足行数预算而拆分页面，也不要将不相关主题合并以逃避计数预算。保留命令和失败契约，删除重复的状态/历史记录，并链接到权威页面。完成的计划和详细的历史实验日志应存放在 Git 历史中，而不是一个不断增长的档案库。针对已建立的比较策略，不得削弱或移除预算；引入此策略没有遗留例外基线。
