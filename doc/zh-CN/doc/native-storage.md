# 原生存储、私有集合和产物准入

[English](../../native-storage.md) · 中文译文，以英文为准。 · [中文目录](../README.md)

在轮次结束且其工作区已被显式收集后，可以收集私有输入副本。一个单独的操作将从基于新修订的输入获取中退役一个被已验收的输出。正式产物字节、检查点负载、发布/工具包文件以及执行/控制证据仍会被保留。这两种操作均不实现正式产物垃圾回收或自动清理。

```text
an-agent-host spool-storage INSTANCE
an-agent-host spool-reclaim-snapshots INSTANCE RUN [--approve HASH]
```

存储查询不会获取执行锁。它报告逻辑文件长度用于释放、工具包、状态、每轮工作/快照/产物以及整个实例，同时还会报告观察到的文件系统可用空间。符号链接不会被跟踪。标记的存在和清理候选项是观察结果，而非删除权限。受限的遍历可能与正在进行的写入发生竞争，因此不是原子的文件系统快照。逻辑字节并非物理节省：APFS克隆和打开的文件描述符在 unlink 后仍可能共享或保留块。

## 独立生命周期

- 释放和选定工具包的字节是执行输入，独立保留。
- 检查点状态是一个显式提交的对象，而非输入快照。
- 正式已验收的产物保持固定版本的发布，供下游检出使用。此命令不能删除它们，也不能将缺失的读者视为同意。
- 工作临时空间使用现有的已批准、终止确认的集合。
- 输入快照保留精确的代码/输入字节，用于短生命周期的诊断。它们的内容随后可能过期；计划、哈希、映射和收据则保持不变。

输入快照路径是私有证据，而非持久产物句柄。下游消费者使用正式的产物检出或显式选择的检查点。回收快照会放弃从这些私有副本逐字节重放；它不会删除独立注册的状态或正式输出。不透明域引用不会通过扫描状态文本推断得出。正式产物删除需要其自身的显式引用/交付合同。关闭新的输入准入是下面描述的独立操作。

## 集合证据

集合持有所属实例和工作区锁，验证本地所有权绑定和现有归档工作集合证据，并检查保留的计划/收据/执行映射。成功输出需要完整的正式接受。注册的状态/产物输入根和当前本地检查点必须保持独立可读。

仅声明的输入文件名及其目录祖先才有资格。
完整的执行快照需要匹配的负载哈希。积极未开始的准备失败可能会有不完整的集合或部分文件字节；
其持久的无生成接收授权检查和精确批准的清理，
从不执行或发布。未注册的文件、链接、未知终止、
更改的完整输入、缺失的根节点和外来所有权拒绝。

预览绑定精确的库存和接收/映射身份。一个排他意图在删除之前存在。一个完整的接收支持只读确认；
一个不完整的删除或丢失的接收返回 `uncertain` 而不重试删除、重新创建数据或制造完成记录。现有的垃圾
必须显式检查。不提供任意宿主路径的递归删除。检查、已验收的产物发现和检查点继续
在成功收集后仍然有效，包括从暂停的实例中。

## 入口压力

工作区准备在复制输入或启动进程之前观察可用文件系统字节。默认最小值是 128 MiB 加上完整的逻辑输入大小，
即使 APFS 可以廉价地克隆这些输入。一个操作者拥有的工作区配置文件可以提升 `minimum_free_bytes`；设置它更低无法绕过下限。
有效的最小值是批准计划的一部分。当前可用空间是执行前提条件，而不是批准哈希内的易变值。

不足的缓冲空间会产生保留的正无生成证据和零自动重试。这是入口回压，而不是原子保留、
运行时配额或防止并发写入填充卷的保证。现有的监督执行和文件权限边界保持不变。

资格包括一个真实的16 MiB输入，保留输入收集后的产物/状态，固定下游传递，暂停/恢复，确认取消，更改/未注册输入的拒绝，部分无生成准备以及丢失接收确认。一个真实的头寸拒绝使用显式提升的操作员请求；测试不会填充用户的磁盘，也不会用模拟器替代文件系统观察。

## 有限私有材料维护

```text
an-agent-host spool-storage-collect INSTANCE REQUEST_JSON [--approve HASH]
```

严格的要求是`{"schema":"an-native-private-collection-request-v1",
"material":"work","runs":["round-0","round-1"]}`。请选择`work`或`snapshots`，使用1..16个唯一且明确的运行名称。这些是独立的阶段：首先收集工作，然后预览/批准快照。不接受通配符、基于年龄的扫描、正式产品/状态选择器或递归宿主路径删除。

宿主会在任何删除之前验证每个选定的原始运行预览。一次批准将绑定物料、实例/发布标识、订单以及所有精确的子库存/证据。每个原始收集操作将在其现有锁下重新验证，并写入自己的持久一次性意图和收据。不会引入新的收集器、删除策略或第二保留账本。更改的所有者/选择/库存无法继承旧的批准。无效、已收集或不确定的项目将拒绝选择，而不是静默跳过。

这不是一个原子的全有或全无的事务。取消操作会在下一个项目之前停止；已承认的子操作将使用其原始协议进行结算。错误或未确认的子结果将停止后续项目，不进行回滚、自动重试或自动恢复。如果客户端响应丢失，请检查现有的每运行收集证据。不要重新发送一批数据以推断剩余项目是安全的：不确定的原始意图仍被封锁。已知未开始的剩余项目需要新的显式选择和批准。

正式产物、检查点状态、发布/套件文件、执行证据和外部输入文件将被保留。被逻辑删除的字节不会在APFS中节省物理空间；此入口点不会声明运行时配额或磁盘保留。真实的macOS资格测试运行四轮，使用8 MiB的外部输入，启动维护的同时，一个独立的下游接收器运行，测量生产者的逻辑足迹，并在收集后确认固定产品和检查点历史记录。它还将在删除前验证维护取消、整体选择拒绝、确认的执行取消以及在进一步删除前丢失的收集收据。这是受控的收据丢失注入，而不是任意的崩溃或断电恢复。

## 停用新的产物输入准入

```text
an-agent-host spool-artifact-retire INSTANCE RUN OUTPUT [--approve HASH]
```

宿主验证拥有实例，成功的整体尝试结算、正式接受和精确声明输出。预览绑定其不可变目录、修订、内容身份和验收证据；批准在该修订旁写入一个专属的`admission-retired.json`闭合记录。没有字节、清单、接受输出绑定或历史事件身份被重写或删除。其他输出和较新的修订保持独立。已提交的检查点目录无法通过此命令退役。

新的基于修订的检出/编辑、原生业务输入选择、工作区制品输入准备和注册的原生修订执行拒绝闭合版本。新的事件发布拒绝它；但现有事件仍可以被读取。未启动的直接/交付/批量预览无法通过旧批准绕过围栏。待处理的库存报告将未启动的交付标记为阻塞。

退役操作使用现有的目录锁和独占标记创建。输入读者保持并发：在获取前后，使用单调闭合围栏检查不可变字节。如果闭合发生在最终检查之前，获取将被拒绝；否则其字节在闭合前已被获取，可能完成。工作区准备在获取其私有输入快照时重新检查。因此，一个并发闭合可能在执行意图被写入后拒绝准备；现有的无生成/不确定证据管理协调，不自动重试。退役不保证每个先前批准的进程已经启动或停止。

证据读取仍与新的输入获取分开。已承认的输出接受、状态提交、因果完成和私有集合仍可以验证保留的字节。从已退役的接受输出提交的检查点是一个独立版本，不是对临时空间的租赁。确认已承认交付所需的结果事实可能在输出承认关闭后仍被记录；它不会重新打开输入承认。

重复一个完整的匹配闭包可以确认其有效性，而无需重写。一个被撕裂、格式错误、链接损坏或存在矛盾的标记会阻止新的准入，并要求进行检查；它永远不会被重试覆盖。此配置文件不支持重新打开或删除操作。`spool-artifacts` 会将准入与它稳定的已接受输出库存分开报告。缺失/损坏的负载仍然会失败证据检查。

这是合作宿主策略，而不是访问撤销或沙箱边界。它不会撤销独立检查出、复制或原始文件输入、缓存或未实现此门控的旧可执行文件。所有受管操作都应使用合格的宿主版本；混合宿主版本是不合格的。原始产物版本方案和发布格式保持不变。

真正的无头资格验证在生产者退役时运行一个接收器，拒绝第二个接收器的过期直接/事件/批量批准，在闭包后完成保管和状态提交，并验证独立检查点、无关输出、取消、保留的字节和撕裂记录的拒绝。不会收集任何正式负载，也不会调用任何模型。

## 原生输入所有权和显式释放

```text
an-agent-host spool-input-references INSTANCE RUN
an-agent-host spool-input-release INSTANCE RUN [--approve HASH]
an-agent-host spool-input-release INSTANCE RUN --delivery WORKSPACE SUBSCRIPTION [--approve HASH]
```

新批准的本地启动会在执行前在源版本处注册每个受管产物/检查点输入。预览不会获取引用。声明将消费者根、实例、发布、唯一运行、确切启动计划摘要、输入槽位和完整源绑定绑定在一起。使用相同版本的两个角色拥有不同的声明。原始文件输入不会获取源声明。历史运行仍可读；一个 `unregistered` 观察结果并不能证明不存在消费者。

消费者会写入一个持久的注册意图，然后在现有目录写锁下获取每个源声明，最后确认注册。本地启动最多有两个受管输入槽位。当一个版本已有512个历史条目（包括声明和发布记录）时，获取将被拒绝；现有所有者仍可记录发布，因此保留的历史条目可能增长到1,024个。不会为了腾出空间而修剪任何历史记录。任何时候只持有单一的源锁，位于消费者现有实例操作中。只读检查不会获取任何锁；它无法授权删除，如果捕获到不完整的发布，可能会失败。目录写冲突仍是一个显式的拒绝，不进行重试或排队。

注册不是跨目录的原子事务。部分获取会保留已写入的声明，并拒绝执行/重用该运行标识。它不会自动完成缺失的声明或回滚所有权证据。源准入闭合仍可在注册后拒绝准备；保留的声明是保守的证据，而不是表示过程已启动的承诺。

原始发布命令仅支持 **已确认取消的运行**，在工作收集和私有输入快照收集都已正确认可之后。它重用原始结算和收集检查，然后将显式批准绑定到这些记录和完整注册。源端发布标记前有一个独占意图。匹配的完整结果可以确认而无需重写；缺失的完成、部分发布、更改的所有者或未知结算将拒绝，不进行修复或重放。源发布永远不会释放其他运行的声明。

`--delivery`形式支持成功的**无状态事件消费者**。它要求确认整个尝试成功，已验收的输出，原始匹配的交付确认以及因果结果事件，加上确认的工作和快照收集。其单独的`an-native-success-input-release-v1`批准绑定该消费确认；原始取消运行计划和CLI仍保持兼容。单个执行退出或已验收的输出无法释放该声明。缺失的确认会拒绝而非调用确认修复。释放是显式的，而不是收集或观察的副作用。

在没有`--coverage`的情况下，成功的释放路径需要恰好一个受管事件输入，且没有显式的状态/数据选择、检查点存储或待处理检查点初始化。有状态的运行会保留其输入，直到操作员单独批准其特定提交检查点的全面覆盖。未启动或部分注册的失败也会保留，等待单独的协调合同。该命令不会删除**任何负载**，也不授予任何收集权限。没有匹配最终消费者确认的源标记仍不确定；释放无法重建该确认或重放工作。现有的产物/释放格式保持不变。混合旧/新宿主、未管理的读者、不透明的检查点依赖和遗留目录会阻止将这些声明视为完整的参考普查。不要从零声明或仅从释放记录推断GC权限。

```text
spool-input-release INSTANCE RUN --delivery WORKSPACE SUBSCRIPTION --coverage FILE [--approve HASH]
```

spool 必须声明并发出文本输出 `checkpoint-input-policy.json`
在 **同一轮尝试** 中与其状态输出一同发出。合格的策略会命名这两个管理角色，并详尽描述该库存中的直接检查点依赖关系。例如，一个保留批次用于审计的计数器会发出：

```json
{"schema":"an-native-checkpoint-managed-input-policy-v1","state_output":"state.txt","data":"checkpoint-pin","parent_state":"not-required"}
```

宿主通过交付收据读取不可变的已接受策略修订版本。
操作员不能用后续文件替换此输出。所有检查点声明中的引脚必须指向这些受管输入。缺少或冲突的策略将拒绝释放，即使操作员声明和正向引脚一致。

`FILE` 在 `schema: an-checkpoint-exhaustive-input-coverage-v1` 下证明所命名的检查点声明涵盖了新检查点的直接保留需求。
它提供了确切的 `checkpoint`、`declaration_sha256` 和有序的 `inputs`。
每个输入都指明其原始的 `catalog`、`revision` 和明确的 `disposition`：
`checkpoint-pin` 或 `not-required`。预览是只读的。批准绑定此证明、原始注册输入、提交和消费证据。

宿主验证提交的祖先是否由此次运行/尝试从该父级产生，重新检查其提交意图和独立检查点引脚，并要求对 **两者** 注册输入进行精确分类。保留的输入必须有匹配的引脚。与引脚冲突的 `not-required` 决定将被拒绝。卷轴作者在其接受的策略中提供语义完整性的判断，用于不透明状态。宿主验证记录的身份和该尝试的受管读取的完整性。未声明的外部依赖关系无法证明其不存在于不透明字节中。证明不提供任何负载删除权限。

在反向装置中，A 是作为新总量的来源而保留的已接受批次，B 是先前的子总量检查点。B 的贡献在新总量中实现。在消费确认和私有集合之后，两个尝试声明释放；独立的新检查点引脚仍然保护 A。不匹配或缺失的输入、承诺、引脚、确认或释放完成将被拒绝。未知的工作永远不会重放。现有父检查点历史记录和其他所有者独立保留其产品。

真实无头接受使用一个生产者、一个成功的消费者和一个独立的已取消消费者。它适用于实时/未知所有者拒绝、工作/快照排序、显式释放、无关保留声明、部分获取、丢失完成和未更改的源负载。宿主拥有此故障矩阵；Loom 仅检查封装的生产者/消费者交接。没有模型或正式负载删除运行。事件情况也适用于成功无状态释放并具有第二个保留消费者的场景，缺少确认/结果/释放收据、过期批准和部分状态初始化。状态情况需要显式覆盖成功有状态释放。不支持的隔离/运行时/网络需求在原生加载前拒绝；不使用后端降级来使这些情况通过。

## 观察一个产品的注册消费者

```text
an-agent-host spool-artifacts INSTANCE RUN --references OUTPUT
```

此可选视图选择一个正式已验收的输出，并检查其确切源版本的本地输入声明。它不获取实例、目录或消费者控制锁，也不会从消费者所有权记录中打开路径。原始的`spool-artifacts INSTANCE RUN`报告和存储的接受身份保持不变。

每个条目区分`claim_without_source_release`与`source_release_recorded`。仅有一个源标记并不能证明消费者已完成最终发布接收。部分注册、成功拥有者和未知结果仍可见；此查询不会进行协调或释放它们。它报告`consumer_receipts_checked: false`、`reference_census_complete: false`和`collection_authorized: false`，包括当目录不存在或为空时。显式的检查点标记现在出现在此清单中，并且不能使用尝试发布标记。旧的宿主、原始文件读取器和未声明的不透明状态引用仍在此清单之外。请参见[检查点依赖项](../../native-state.md#explicit-checkpoint-artifact-dependencies)。

该查询检查源绑定、内容寻址声明文件名和配对的发布标记。孤儿、格式错误、外来、链接或过大记录在未修复的情况下将被拒绝。检查范围限制为1,024个目录条目、每条记录64 KiB和8 MiB的紧凑JSON声明数据。这不是一个原子快照：并发发布可能在视图中缺失或导致拒绝。此视图不能用作删除的前置条件。不会引入后台轮询、重试或负载删除。所有者路径是私有的操作证据，而非发布数据。

真实接受扩展了现有的生产者/两个消费者情形：在消费者运行期间，传入声明是可观测的，同时源控制锁被持有；部分注册仍可见；确认取消会创建一个源标记，同时另一个消费者仍被保留。移除消费者完成接收并不意味着该标记变为完成发布的保证。格式错误的源证据将被拒绝，所有原始负载哈希保持不变。

## 验证一个已验收的输出

```text
spool-artifacts INSTANCE RUN --output OUTPUT
```

此检查验证原始结算、执行、实例所有权、接受意图以及完整的声明输出清单。它会将**每个修订清单**与内容地址、预期路径、大小、内容摘要和尝试来源进行比对。然后它会读取并哈希所选的负载。结果识别出一个输出在`an-native-selected-artifact-v1`下。其他负载的可用性不在此次结果范围内。源引用视图和退休审查使用相同的所选输出验证。

缺失或损坏的兄弟负载会使所选输出可被检查。缺失或损坏的所选负载会拒绝检查。损坏的共享验收证据或兄弟修订元数据仍会使得清单无效。仅有缺失的字节并不能提供已授权删除的证据。需要整个运行证据的完整运行检查和操作仍保留其完整的负载检查。

## 在收集前审查已退休的输出

```text
spool-artifacts PRODUCER RUN --review-retirement OUTPUT [CONSUMER_ROOT ...]
```

首先退役确切的已接受修订版本。仅提供那些本地记录可以打开的消费者实例目录。如果没有消费者参数，该命令只会读取生产者。正常的`--references`视图会保持其仅源合同。

审查区分了检查点钉住、未释放的尝试声明以及消费者未被选中的源标记。对于已选中并释放的尝试，它会检查确切的引用槽位和原始注册信息，与开始、已结算的接收和终止证据，不可变释放意图的摘要，以及匹配的消费者完成情况。缺少或外来的接收会导致`release-unconfirmed`。`release-confirmed`验证该引用的历史释放情况。它不会授予新的释放或重新授权交付。通过源声明打开路径不会发现任何消费者根节点。原始的每运行注册信息会在本地检查，而无需遍历其其他目录。

限制为16个已选消费者和64个源声明。格式错误的源证据将拒绝审查。结果是非原子性的：未确认的结果可以再次检查，但不会触发修复或执行。即使一个已退役的输出带有零个声明，也会报告`collection_authorized: false`；现有的目录可以有未管理的和遗留的读者。真实的共享源CLI测试会移除和交换完成接收，并验证其他检查点钉住和源字节是否保持完整。

## 注册副本和显式负载删除

在首次接受时，操作员可以选择`spool-accept INSTANCE RUN --registered`。请分别预览和批准此操作。该新每运行目录的所有输出都会获得一个不同的注册文本或二进制修订方案。不可变的接受意图记录了配置文件。宿主会在发布修订版本之前，先将字节和空的读者账本一起进行阶段处理。普通接受会保持其现有格式。现有的目录无法通过此命令被采用、升级或收集。

每个版本都有一个与其规范目录和修订版本绑定的私有 SQLite 数据库。SQLite 对准入、PIN 创建、复制完成、释放和关闭进行序列化。原生事件传递或显式数据/状态启动会绑定确切的源版本，包括当启动由独立监督时的情况。预览会返回其身份。批准后，宿主会在源账本中保留消费尝试，然后将其字节复制到私有输入快照中。一个被准入的尝试可以在关闭后完成。通用工作区配置文件和检出/编辑命令无法读取这些字节。使用注册的检出方式用于独立文件。每个声明的检查点依赖项都会拥有自己的 PIN。私有对等体交换和将注册输出提升为新检查点的推广仍在此输入配置文件之外。

```text
spool-managed show INSTANCE RUN OUTPUT REVISION
spool-managed checkout INSTANCE RUN OUTPUT REVISION READER NEW_FILE [--approve HASH]
spool-managed close INSTANCE RUN OUTPUT REVISION [--approve HASH]
spool-managed release INSTANCE RUN OUTPUT REVISION READER [--approve HASH]
spool-managed delete INSTANCE RUN OUTPUT REVISION [--approve HASH]
```

每个变更都需要其自己的预览摘要。一个复制读取器在接收到字节之前会保留其名称。成功的独占创建和同步其独立文件先于持久化完成。显式的读取器释放要求该完成。中断的复制保留其保留状态，即使目标文件已存在。关闭准入会新建读取器和过期的检查出批准。它允许一个已经准入的读取器完成并释放。读取器身份是单次使用的，每个版本最多128个，包括检查点保留。关闭准入不会释放检查点依赖。源接受检查点保留释放仅在完成[检查点退休](../../native-state.md#explicit-checkpoint-retirement)接收后。

删除需要确认关闭，每个已准入读取器的有效释放以及该确切接受输出的验证字节。对于本地尝试，宿主将它的源声明和释放标记与消费者的原始注册、结算、释放意图和最终接收进行匹配。缺少消费者或中断的释放即使源标记存活也会阻止删除。删除意图绑定释放摘要，因此如果消费者之后离线，完成的接收仍可读。它首先提交一个单次使用的意图。第二次事务移除BLOB并提交其匹配的接收。数据库争用或中断的操作会返回供显式检查；没有自动重放或意图修复。仅在确认BLOB、意图、释放证据和匹配接收都不存在后才显示报告`deleted`。缺少字节、缺少数据库或损坏的记录无法证明删除。没有最终接收的持久化意图仍保持`deletion-unconfirmed`。整个运行的历史证据和选定的完整兄弟节点仍可验证。对已删除版本的内容请求会失败。接收记录逻辑上已移除的字节。文件系统快照、导出的副本和备份具有独立的保留。

读者普查覆盖了通过已审查的本地宿主进行的应用程序交接，该宿主对其私有存储拥有独占保管权。当前宿主拒绝将数据库作为原始输入，并且其本地工作区策略即使在更广泛的运行时读取根目录下也禁止访问备份文件和SQLite辅助文件。具有直接文件系统访问权限、特权外部软件、较旧的宿主被授予原始存储访问权限，以及对活动存储进行就地回滚的管理员，均位于此信任边界之外。请保持目录私密。一个普通的传统目录从空的观察参考列表中永远不会符合删除条件。

真实的macOS无头套件使用一个二进制负载和一个文本兄弟文件。一个保留的检查点和一个注册的副本读取器各自阻止删除操作。在关闭并确认释放之后，它会删除二进制版本，读取保留的副本到第二个存储区，并验证兄弟文件和历史库存。该套件注入一个丢失的副本完成、一个缺失的负载以及在BLOB移除和接收发布之间的失败；事务回滚并重放意图围栏。
