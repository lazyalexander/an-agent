# 状态、制品和历史

[English](../../state-and-artifacts.md) · 中文译文，以英文为准。 · [中文目录](../README.md)

这些是不同类型的资产，拥有不同的所有者和恢复保证。

| 资产 | 含义和所有权 |
| --- | --- |
| 发布 | 不可变的领域实现和依赖项；以包的形式被识别和保留 |
| 实例状态/检查点 | 由Spool定义的业务持续性数据；宿主管理身份、版本、提交前提条件和保留的引用 |
| 制品 | 明确接受的产品字节、不可变的修订和来源；宿主托管使选定的版本可供下游使用 |
| 内部工作文件 | 默认为一次性使用文件，包括临时套件和适配的套件工作副本；可选的恢复/调试保留是显式的 |
| 磁带和边界收据 | 因果/诊断历史、权威和结果证据；不是完整的世界备份 |
| 后端磁盘或内存快照 | 后端特定的执行状态；可选且与可移植业务状态不同 |

一个发布加上足够的已提交检查点可以支持在一个全新的环境中进行新的尝试。Spool定义其状态是否足够；宿主无法从不透明字节中认证业务完整性。这不会重新创建旧的进程内存、缺失的包、不可用的模型或外部影响。

请参阅[Spool代码合同](spool-code.md)，了解不可变的Silk/包字节、可编辑的套件副本、显式的推广和代码作为数据的执行限制。

## 发布和消费

输出在宿主接受之前始终是候选状态。人工编辑使用一个单独的工作副本；提交保存的字节会创建一个新的修订版本，并以父版本为基准。它不会覆盖已接受的版本。人工编辑的来源是显式的操作声明，而不是加密的作者证明。

下游尝试绑定精确的修订版本和摘要，而不是可变的最新指针。较新的版本不会更改正在运行的输入或授权重新运行。现有的实例提交会检查预期的状态头并拒绝过时的更新。可选的检查点/交付合同记录选定的接收者、状态引用和已提交的消费。缺少确认本身并不授权重复执行。

## 保留和中断

正式的状态/制品存在于一次性执行的临时文件之外。它们必须在可回收的临时文件收集过程中幸存下来。保留的状态引用和未解决的交付/执行证据可以防止产品回收。成功的消费者确认本身并不等于删除权限。

原生已验收的输出可以独立关闭基于新修订的输入准入。这保留了不可变的负载、已接受的执行/托管和独立的检查点；它不是参考释放收据或删除字节的权限。私有工作/快照收集保持独立。请参阅[原生存储合同](native-storage.md)。

固定的原生文件配置文件允许在确认取消后进行显式的回收，以及成功后进行回收。取消的部分输出永远不会发布或用作能力请求。缺少结算或未知的终止拒绝清理；失败和超时的运行仍在此清理政策之外。

中断的尝试保留不确定性以及所需的诊断/恢复数据。在可能的写入者仍存在时，不要收集目录。当前的回收是有限的和显式的；没有通用的周期性收集器或完整的断电恢复保证。工作流引擎的恢复缓存对宿主保持不透明，并且在其临时文件被回收之前需要显式的放弃。

停止的环境不是一个独立的备份。磁盘重启、内存恢复、状态迁移和外部软件更改的撤销需要不同的合同。

## 不透明的临时存储和借用输入

未声明的内部文件不是发布的产品或隐式状态。安全清理的运营库存/限制仍需与业务级别的索引区分开来。外部只读访问可以避免额外的文件复制，但不会冻结其他应用程序可能更改的源。固定版本的输入需要受管理的不可变字节或合格的快照；实时输入不得声称具有该保证。请参见 [handoff pressure decision](testing.md)。

所提出的 [session and retention plan](session-and-retention.md) 将证据引用、显式字节保留锚点和独立副本分开。其中描述的原生锚点账本、正式负载收集器和会话协调器尚未实现。
