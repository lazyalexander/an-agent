# 执行与权威

[English](../../execution.md) · 中文译文，以英文为准。 · [中文目录](../README.md)

一个管理生产的尝试必须识别其拥有者spool释放、选定的输入/状态、有效授权和后端。内部silks在该边界内运行。一个silk调用不是另一个虚拟机的默认请求。开发工具可以调用独立程序，但单独调用并不构成管理spool的执行。

## 宿主拥有的流程

1. 验证不可变的释放/输入身份以及请求的操作。
2. 评估声明和相关当前事实，而不将其视为授权。
3. 解决一个操作员授权的计划和适当的执行配置。
4. 在提交前记录操作意图。区分宿主操作身份与后端环境身份和运行时生成。
5. 在选定的边界内执行。内部域序列保持在spool中；外部能力需要宿主授权的接口。
6. 重新协商实际结果、取消状态、环境身份和终端结算。在发布前验证声明的候选输出。
7. 通过其支持的宿主合同提交官方输出/状态，并保留证据。在完成所需结算检查后，才可回收可选的scratch。

现有的宿主后端合同实现了本流程的一部分，用于Native和OpenShell单入口部署。它是内部的，不是稳定的通用插件API。已审查的工作空间作业是另一个独立的信任操作员配置；它们尚未承载完整的生产spool权威或敌对代理隔离。

## 语义评估与硬限制

语义平面检测并报告发现。它不调度工作、分配虚拟机、取消执行或联系监督代理。宿主/控制层决定如何处理发现并请求审查。执行边界独立于模型判断来实施权限。声明通过政策检查或记录接收并不本身构成执行。

## 取消、失败和不确定性

取消请求、CLI退出和确认环境终止是不同的观察。silk子进程退出并不证明兄弟或逃逸工作进程已停止。目标整个spool边界必须在结算或清理之前考虑所有拥有执行。
当前配置具有不同的资格范围。Native审查的工作流程需要不脱机或逃逸其进程组的协作工作者。OpenShell额外要求相同拥有环境和生成的停止确认。不应将这些 generalize 到不支持的工作负载。

未知提交或终止被保留用于 reconciliation，不自动重试。超时/取消的尝试不能以成功状态发布延迟结果。宿主崩溃、外部影响和远程工作者需要超出本地进程退出的证据。不要从操作日志推断持久崩溃恢复。

## 后端和应用程序边界

OpenShell是可选的；Native配置使用其现有的操作系统特定限制。OpenShell扩展在native审查的头less生命周期和托管完成时暂停。保留适配器及其失败测试，而不将其作为默认运行依赖。选定的后端必须满足所需隔离；缺少支持将拒绝，无自动下放。通过Loom检查或运行头less并不使生成的代码成为合作可信工作者。隔离、凭证、网络、配额、暂停和快照是独立能力。上游后端支持不证明我们的适配器暴露或已合格。不要为每个内部silk添加一个后端。

用户应用程序除非明确放置在spool环境中，否则仍保持在spool环境之外。一个信使中介了授权的外部读/写操作与选定版本和实际效果凭证。文件系统备份无法撤销消息、远程API调用或任意GUI操作。

## 同时进行的原生尝试

宿主拥有轻量级尝试协调；它不实现新的容器运行时。原生执行是第一个本地后端。容器或微VM支持仍作为独立资格的后端选择，而非将制品所有权或领域序列迁移到该后端的理由。

现在固定原生文件配置允许在同一个宿主存储中独立进行尝试。存储锁保护释放分辨率、输入快照和独占运行目录分配，然后在准入和进程启动前释放。每个尝试拥有自己的目录、AgentControl线程、操作身份、子进程和取消标志。短共享元数据操作仍因锁竞争而失败；没有新的队列、过期锁修复或自动重试。正在运行的子进程不再为它的整个生命周期持有该锁。

存储锁的缺失而非存储锁的存在是清理的准入条件。一个新的尝试是一个显式的调用，带有新的身份，而不是取消内存的恢复。业务状态是显式选择的。操作系统线程和进程内存属于后端；没有承诺可移植的线程快照。接受的文件修订版本在尝试之间传递数据，小控制通知仍保持分离。

在`tests/file_runtime/concurrent.rs`中，真实的CLI回归开始在一个存储中创建两个命名的spool释放，通过SIGTERM取消一个，重新获得其确认取消的工作并启动一个新尝试，同时其同伴继续进行。同伴锁定v1，完成后在v2发布后保留v1输出直到清理。这符合现有的单入口文件ABI，而非任意多silk进程树、敌对同一用户进程、持久环境或VM备份。Loom仍然作者、检查和打包发布；它拥有这些运行时锁、授权、取消或保留决策的全部权利。

对于可重复的本地证据：

```sh
AN_AGENT_ACCEPTANCE_DIR=/absolute/path/to/evidence \
  cargo test -p an-agent-host --test file_runtime concurrent -- --nocapture
```

报告包含相对事件时间、完整计划、操作ID、子PID、接收记录、结算/审计记录、修订绑定和回收结果。这些合成测试记录可以包含本地路径：在共享之前检查。CI保留报告按操作系统保留；时间是诊断证据，而不是基准。

## 一个审查体与两个丝线

经过审查的体路径运行一个协调器和两个内部丝线进程通过现有的审查工作空间配置文件([平台资格](platforms.md))。一个进程组、尝试和取消操作所有者覆盖整个循环。生产者将内部文件传递给消费者，消费者提供候选，只有完整循环结算才能授权宿主复制/验证和发布。一个零退出领导者与被放弃的成员在强制清理后失败，而不是成功。绑定到释放的原生面也符合两个内部丝线步骤； neither 路径为每个丝线提供独立环境，也不将域序列移动到宿主。

[实现与压力计划](testing.md)将当前回归/ soak 证据与未来饱和和崩溃故障测试分开。这不是一个通用注册的多丝线部署或一个敌对代码沙箱。在设计另一个包 ABI 之前，应重用当前的权威边界； Loom 仅负责开发和打包。

### 艺术品描述符和工具身份检查

原生文件-kit 收集器以 `O_NOFOLLOW | O_NONBLOCK` 开始，然后检查并读取与受限、单链表的常规文件相同的描述符。描述符和普通读取共享注册的托管权和侧边车原始路径拒绝。Linux 读取其原始宿主拥有的输出描述符，并且单独拒绝路径名 inode 替换；它从不接受从重新打开的替换路径名中的字节。批准的 Rust 构建在每次编译阶段前重新哈希编译器和链接器。一个不匹配会拒绝该阶段，而无需自动重试。这检测在批准后的变化； 信任的工具链目录仍必须排除不信任的写入者，因为路径名哈希不是原子可执行启动或完整的依赖哈希。

## 可选 SPACE 文件执行

`an-agent-host run-space PROFILE STORE RELEASE INPUT [--execute]` 复用现有
ExecutionBackend 的注册、准入、不可变程序发布、操作结算、取消检查与产物接收。
不带 `--execute` 只预览；不建立并行 host、产物库或模型驱动，也不回退到本地执行。

私有配置包含 `python`、`python_sha256`、`client`、`client_sha256`、`token_file`、
`api_url`、`data_plane_url`、`template` 与 `control_seconds`。使用无符号链接的绝对
路径及完整摘要，client 选择固定版本 SPACE 官方 first_sandbox.py。令牌文件仅允许
操作者读取；不会送入 guest。模板必须为完整 NAME@sha256:DIGEST，不接受可变标签。
控制阶段限时 30–180 秒，另有有限本地进程回收时间。

初版仅接收至多 256 KiB 的 Linux 程序或 guest 可执行脚本；输入上限 8192 字节，
UTF-8 产物上限 65536 字节。模板需包含 root Python 3 和程序依赖。程序以 UID/GID
65534 使用固定 input.txt/output.txt ABI，程序、输入和目录由 root 保护。允许 guest
临时目录，禁止网络出口和宿主挂载；链接、非普通文件、超限候选均拒收。

提交前记录操作及请求键，不自动重放。元数据绑定 run 和 operation，清理校验同一
sandbox、创建时间与模板摘要。取消工作阶段后独立尝试删除；只有删除操作完成才
能接收产物。若创建响应丢失导致缺少安全清理目标，记录终止未确认并保留现场，
由操作者核实，不猜测 ID；这不是持久崩溃恢复或自动远端垃圾回收。

本地故障测试通过真实注册、准入和 receipt 路径；不代表产品适配器已通过云端、
任意 guest 或 CAD→Krita 验收。此前云端日志实验采用实验应用，不能作为正式
native-spool 托管验收。完整英文契约位于 doc/execution.md 对应章节。
