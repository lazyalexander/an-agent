## 已审查的本地工作区任务

此受限于macOS的配置运行一个由操作员选择并已审查的本地工作流引擎，并管理其scratch和已选的UTF-8输出。它重用原生的supervisor、独占宿主存储和现有的不可变构件版本目录。它不将Nextflow、Loom或一个域调度器作为宿主的一部分。

这是一个操作员开发/验收的边界，而不是一个新的spool部署ABI或一个不受信任的代码代理执行配置。现有的文件/标准输入输出套件保留其更严格的进程和文件系统限制。

### 权限和配置

调用者选择一个私有的JSON配置文件，该文件位于任务之外。从spool、模型输出或可写项目配置中不要接受此配置作为权限。

```json
{
  "schema": "an-workspace-job-v2",
  "executable": "/bin/bash",
  "args": ["{input:0}", "--output", "{work}/result.txt"],
  "environment": {},
  "readonly": [],
  "inputs": ["/operator/selected/runner"],
  "outputs": ["result.txt"],
  "wall_seconds": 60,
  "trusted_process_group": true
}
```

`{work}`，`{input:N}`（零基索引选择的输入）和`{inputs}`（快照目录）在argv和环境值中展开为字面量；宿主不添加shell解释。选定的文件需要唯一的UTF-8基名，不含括号。使用占位符而非原始选定路径在参数或环境变量中。V1配置文件被拒绝；必须显式更新其模式、输入参数和运行时根目录，而非隐式改变其执行语义。明确选择`/bin/bash`是选择一个shell。计划显示精确的命令、环境、选定输入哈希值和有效Seatbelt策略。环境继承被清除；PATH、TMPDIR和LANG固定。运行时根目录必须排除宿主作业及其祖先，并且不能包含选定输入。批准后，宿主将选定字节复制到一个全新的私有快照中，检查其批准的哈希值，并记录解析后的执行映像。选定的原始路径被禁止在工作负载策略中读取和执行；快照是只读的，并且位于可写沙盒之外。钉住的构件从其不可变分类版本复制，而非可编辑的检出。在快照验证前，任何更改的普通输入都会拒绝准备；不会启动任何工作负载。

在macOS上，普通选定文件首先使用基于描述符的文件系统克隆。支持相同卷的文件系统使用复制-写入方式共享块，使用新的私有inode而非硬链接或活源挂载。目标仍会检查批准的摘要。仅当不支持的卷或跨设备错误时，才会选择现有的完整复制路径；权限、大小、已存在目标和其他错误将拒绝准备。构件目录输入保持其已验证的复制路径。输入限制和CLI模式保持不变。参见[外部输入克隆资格](artifacts.md)以获取测量和限制。

输出接受验证了绑定执行映像、其从批准计划的精确映射以及快照哈希值。源文件随后可能改变或消失，但不会破坏那些持久的输入字节。缺失或替换的快照证据拒绝接受，包括旧尝试但无该证据的尝试。这不会改变现有的终止门限，用于继续或收集。准备失败和取消记录显式的无_spawn证据，当该证据可以持久写入时。它们从不自动重试或提升部分快照；请参见预启动生命周期以下。

运行时可执行文件和目录依赖项仍由操作员控制，并且**不快照**。可执行文件仍具有前/后哈希检查；这些不关闭替换和恢复比赛。复制一个苹果平台可执行文件失败了原生资格，因此此切片不搬迁、重新签名或静默替换解释器。这是选定输入的托管，而不是一个封闭的无交互运行时或对恶意同一用户进程修改宿主证据的保护。

macOS策略允许标准系统工具和选定的运行时根目录被读取/执行，并且仅在`work/`和`/dev/null`加上的情况下允许写入。网络操作被拒绝。合格的JVM还需要特定的`com.apple.system.opendirectoryd.libinfo` Mach查找用于用户属性启动；允许任意Mach服务是不必要的。进程元数据查询和信号仅限于同一沙盒。在Linux或其他不支持平台上没有回退；其现有的宿主配置文件保持不变。

### 运行、中断并显式继续

```sh
an-agent-host workspace-run PROFILE NEW_JOB
an-agent-host workspace-run PROFILE NEW_JOB --approve REVIEWED_DIGEST
## SIGINT/SIGTERM requests cancellation of the host-owned execution.
an-agent-host workspace-resume PROFILE JOB PREVIOUS_ATTEMPT
an-agent-host workspace-resume PROFILE JOB PREVIOUS_ATTEMPT --approve REVIEWED_DIGEST
```

已取消的已批准呼叫返回 `status=cancelled`, `executed=false` 和 `process_started=false`，不创建工作区、尝试或继任者。预览仍为只读预览。在这种情况下不返回尝试ID。

每个分配的尝试具有新的UUID，并记录其计划、意图和一个临时 `an-workspace-not-started-v1` 接收（`stage=prepared`）在发布其前继者的继任者指针之前。该指针从完整字节中原子地发布。未发布的延续不能授权回收共享工作区。发布后，后续决定针对继任者。临时接收是有序预发协议的正证据，而不是从缺失的PID推断出的结论。它仅在 `launch.json` 不存在时使用，并且其前继者指针存在时，该指针绑定此尝试和批准。在进入监督者之前立即，宿主持久化 `launch.json`。该标记即使进程从未实际启动，也会无效临时无孵化权。最终接收原子地替换仅临时接收；替换失败则保留启动围栏的效力。

取消或失败在准备期间，以及在启动前由监督者显式返回的取消，产生 `an-workspace-not-started-v1` 接收。这些绑定计划和意图，记录阶段（`preparation` 或 `supervisor`），并包含 `process_started=false`, `pid=null`, `exit_code=null`, `reaped=false`, `group_cleanup_required=false` 和 `termination_confirmed=true`。此处终止表示未启动任何进程，而不是虚构子进程被终止。准备错误保留拒绝证据。无论哪种情况，都不发明空进程组观察。

有效的未启动接收允许通过现有API显式批准继续或擦除放弃。即使scratch包含先前尝试的成功输出，它也不能发布输出。已验收的产物修订仍处于回收之外。缺失/矛盾字段、更改或缺失意图、或不成功的接收写入，均不授予生命周期权限。一个spawn/pre-exec错误仍不确定；缺少PID本身从未是无孵化证明。在启动围栏之前崩溃可能留下可使用的已提交预发证据。在围栏之后崩溃、缺失/损坏的接收或不完整的旧版尝试仍需调查。
没有自动重试、接收修复或推测进程清理。宿主保留有限的stdout/stderr和一个接收，即使后运行库存无法收集。缺失接收、未确认终止、活跃宿主锁或已选的继任者围栏进一步延续和收集。前继者和scratch库存绑定于批准。没有过时锁被移除，不确定结果后没有自动重试。

接受、继续和回收共享同一个接收门。对于已启动的尝试，现有的 `an-workspace-receipt-v1` 路径需要显式 `termination_confirmed=true`, `reaped=true`, 一个正过程ID，以及一个绑定到该ID的空进程组观察，且无观察错误。`group_cleanup_required` 必须是布尔值；成功尝试必须显式记录 `false`。旧版v1接收中缺失/缺失/矛盾字段、更改或缺失意图、或不成功的接收写入，不授予终止权限，包括失败或取消的接收。它们保留用于检查；这些操作拒绝而非推断安全默认值、重写历史或启动继任者。新未启动方案是明确宿主证据，而不是对不完整旧版接收的重新解释。`tests/workspace_job/settlement.rs` 中的测试移除字段并执行预览和先前批准请求。

延续会保留引擎的工作文件和缓存至相同路径。调用者提供引擎自身的恢复参数；宿主不重建其内部任务图或推断哪些任务应重新运行。一个恢复的引擎可能内部重新尝试/重新计算其任务；宿主 `automatic_retries: 0` 描述宿主提交策略，而非引擎语义的覆盖。

### 分离输出接受和收集

```sh
an-agent-host workspace-accept JOB ATTEMPT
an-agent-host workspace-accept JOB ATTEMPT --approve REVIEWED_DIGEST
an-agent-host artifact-checkout JOB/artifacts REVISION NEW_EDITABLE_FILE
an-agent-host workspace-reclaim JOB ATTEMPT
an-agent-host workspace-reclaim JOB ATTEMPT --approve REVIEWED_DIGEST
```

只有成功且已确认终止的当前尝试才能提供其声明的输出槽位。输出接受器会读取绑定的定期非链接UTF-8文件，预览其精确的哈希值，然后通过现有的构件目录进行发布。领域正确性由工作流/分发区的责任承担。失败或取消不能促进部分输出的发布。一个独占的接受意图会防止重复/部分发布；未知的结果需要调查，而不是重试。这并不是一个原子的多构件事务或迁移/状态提交。

Scratch 会在明确批准收集之前保留。收集意味着**放弃引擎继续执行的权利**。成功的尝试需要先前已接受、仍有效的构件版本。一个确认失败/取消的尝试也可能被明确放弃；其部分工作并不构成正式的构件。批准的无跟随库存覆盖整个工作树，包括原生缓存和未声明的临时文件。尝试输入快照保留为证据，而非scratch；此切片不为它们添加保留/GC策略。符号链接未被解除链接，永不被遍历。常规硬链接和特殊文件会导致拒绝。一个变更的库存需要重新获得批准；部分删除被一个不可逆意图包围，且不支持重试。

接受的修订版本、输入快照、凭证、计划和受限诊断流保持在不可写/回收的树之外。现有消费者可以继续在收集后选择相同的修订版本。此处不重新实现形式化构件GC、交付订阅和领域检查点完整性。

### 布局和限制

```text
JOB/
  attempts/UUID/   plan.json, execution.json, intent.json, stdout.txt, stderr.txt, receipt.json
                  snapshot/inputs/ (approved selected bytes, retained evidence)
                  successor.json, accept-intent.json, accepted.json (when applicable)
  work/           engine-owned private workspace and recovery data
  artifacts/      existing immutable artifact revision catalog
  reclaim-intent.json, reclaimed.json (after explicit collection)
```

用户配置文件限制墙时间到1–300秒，流到64 KiB每个，单独生成的文件到64 MiB，库存到2000个条目/32个目录层级/128 MiB，以及声明的交付成果到16个文件，每个文件大小不超过64 KiB。总空闲空间限制在库存过程中检查，而不是强制执行磁盘配额。运行时依赖项是只读能力，而不是一个封闭或可重复构建的认证。

监督者拥有一个进程组，回收其直接子进程，并在声明终止确认前要求空组观察。回收后，对其进行上至1秒的受限只读观察；这并非执行重试，且在此观察窗口内不会重新使用已有的数值组。接收的记录保留组身份、空状态、样本数量、观察时间及错误。如果协调者退出而同伴仍存在，所需强制清理被记录，并且即使领导者退出码为0，该轮也无法成为成功。审查过的工作者必须不启动守护进程、改变进程组或启动远程工作。组空状态不能证明已逃逸/远程的工作者已停止。此边界不支持此类工作负载或由恶意代理生成的代码；需要更强的资格认证后端。宿主崩溃和SIGKILL保留过期锁：操作员必须在清除它之前确认其所有者和任何工作者均已离开。宿主不清理过期锁或从PID缺失推断所有权。一旦该独立步骤完成，已提交的预启动记录可授权显式继续或收集。已启动/未确认的尝试、恶意同用户重命名和电源中断保留原有的手动调查限制。未引入任何虚拟机框架或自动GC服务。

### 接受

`cargo test -p an-agent-host --test workspace_job` 用于实际执行 Seatbelt 执行、网络/外部写入拒绝、取消、超时、当前尝试检查、拒绝链接/失败输出、更改批准和接受版本的生存度，以及在 scratch 收集后存活。外部 Nextflow 接受在 an-loom 中也发送一个真实的 CLI SIGINT，在任务执行过程中恢复，通过原生引擎缓存，并在重新分配后消耗已锁定的输出修订版。原生磁带保持引擎/代理所有；宿主记录其边界证据，而不是内部重放。

#### 可选二进制输出和已锁定的制品

添加的 `binary_outputs` 列表选择已声明的输出进入受限的透明字节托管；缺失的条目保持纯文本行为。`artifact_inputs` 可将选定的只读快照绑定到 `{ "path": "/selected/snapshot",
"catalog": "/host/catalog", "revision": "FULL_SHA256" }`。目录不挂载或传递给工作负载。缺失的修订版、替换的快照、重复绑定和更改批准输入被拒绝。
见 [artifact 版本语义](artifacts.md)。这些是通用文件能力；工作簿解析和呈现组合属于 kit。

#### 两个内部丝线和压力资格

#### 有界恢复回归

[多丝计划](testing.md) 定义了不变量、托管转移、锁作用域和分阶段压力测试。真实 macOS 测试用例使用一个协调器、一个生产者和一个消费者，它们在同一原生组中运行，没有为每个丝线单独运行。它覆盖了在手交之前/之后的取消、早期领导者退出、丝线失败、超时、不确定的观察结果以及在复制之后锁定的下游消费。显式忽略的 soak 运行了四个独立的作业，每个作业进行十轮混合轮次。该过程通过现有的工作区配置进行审核；它不创建已注册的生产多丝包 ABI。

`cargo test -p an-agent-host --lib workspace_job::recovery_tests` 运行一个真实的宿主子进程，该子进程在四个持久边界处退出时没有进行 unwind 操作。每个子进程都有一个 15 秒的外部截止时间，并且使用极小的输入。测试在显式移除其过时锁之前，会先验证子进程退出是否及时，然后检查当前尝试的权威、延续、集合预览、拒绝发布以及保留的正式输出。它们不声称自动恢复过时锁或电源中断的持久性。

大型文件托管仍作为一个单独的 64 MiB 测试运行，与之前的准备度和执行截止时间保持一致。测试配置仅优化 SHA-256，同时保留正常的 Rust 宿主调试检查，避免在 CI 中使用未优化的哈希作为速度要求。

Python 或 TypeScript 可以驱动外部接受场景；将断言移出 Rust 无法加速宿主的快照或哈希路径。持久性顺序和故障窗口仍与 Rust 实现进行测试。

### 保留一个已审查的输入树

`an-workspace-job-v2` 接受一个可选的 `input_layout` 数组，与 `inputs` 平行。省略或空数组保留现有的基名布局和 CLI 行为。非空数组必须为每个输入指定一个唯一的可移植相对路径。例如，两个来源可以映射到 `project/silk/main.sh` 和 `project/kit/main.sh`，即使它们的源基名相同。

宿主检查遍历、重复目标、文件/目录前缀冲突以及 16 组件深度限制。现有文件计数和字节限制保持不变。映射参与预览批准、不可变输入快照、执行身份和接受复核。父目录仅在宿主拥有快照时创建，且已存在无链接检查。`{input:N}` 解析选定的叶子；`{inputs}` 仍为快照根。工作负载不能编辑此树。可写结果属于 `{work}`。

Loom 使用这个通用文件映射来检查一个冻结的候选项目。宿主不解析 Loom 任务、选择领域测试、打包发布或评估业务正确性。操作员仍审查生成的 profile 并分别批准执行和正式输出接受。现有的原生信任进程组作用域不变；这并不构成 hostile-agent 含义。

## 有限的 Rust 构建和文件-kit 交接

此切片添加了一个具体的构建配方和一个文件 ABI。它不添加工作流框架、包管理器、代码生成器、容器适配器或 SPACE 后端。核心保持不变。Loom 搭建并打包；此宿主执行。

### 构建契约

`an-agent-host build-kit SOURCE TOOLCHAIN_JSON NEW_JOB` 预览源哈希、工具指纹、精确参数、工作目录、环境、策略、输出边界和限制。它创建 no job。操作员审查计划并用 `approval_sha256` 传递给 `--approve`。更改的源/配置/路径/工具会无效该批准。已有的 job 从不会被覆盖或自动恢复。

工具链 JSON 包含恰好 `rustc`、`sdk` 和 `linker`：具体 Rust 编译器（非 rustup shim）的绝对路径，选定的 macOS SDK，以及 clang。使用 `rustc --print sysroot` 和 `xcrun --show-sdk-path/--find clang` 来定位操作员安装的工具。它们是受信任的依赖项；这并不构成编译器/SDK 供应链认证。完整的 SDK/工具链树不进行哈希。在预览和运行期间，保持工具和作业父级私密，以供受信任的操作员使用。

| 阶段 | 读边界 | 写/处理边界 |
| --- | --- | --- |
| 编译器 | 源代码，选定的Rust/SDK/链接器树以及操作系统运行时数据 | 作业构建目录；选定的可信编译器/链接器程序 |
| 测试 | 测试可执行文件和操作系统运行时数据 | 不写文件，网络或子进程 |
| 验收 | 宿主检查精确的源代码/程序文件 | 新接受的目录，对任一工作负载都不可访问 |

编译过程可能读取批准的工具链/SDK树中的数据。不要将秘密放置其中。系统库/元数据的读取是必要的允许，而不是声称对整个文件系统完全不可见。没有转发的环境变量。本地作业和Rust工具链源路径在生成的二进制文件中被重映射。这减少了路径泄露，而不是用户源代码中任意的私有字符串。

每个阶段都有60秒的墙限制和每捕获输出流64 KiB的限制。编译器写入有20 MiB每文件的限制；没有总磁盘/内存配额或恶意编译器隔离。测试使用更严格的无写入/无子进程政策。固定测试命令使用一个测试线程；作者仍可以编写昂贵的测试，因此监督者仍然具有权威性。

真实 AgentControl 注册，描述的 mount、请求、承认意图以及磁带均在编译之前。宿主将内部 `/job` 声明槽绑定到计划中的新作业目录。只读工具链输入是额外的计划允许项。作业状态、受限流、PID/回收证据、接收和核心审计结果仍保留在作业中。只有完成成功才获得 `applied`。通过测试是提供测试的证据，而非领域正确性的证明。

### 资源接收

成功时，`accepted/` 包含 `main.rs`、`program` 和 `manifest.json`。可移植的 `an-rust-build-artifacts-v1` 显式绑定两个 SHA-256 哈希值和 passing-test 状态。 enclosing `an-rust-build-receipt-v1` 记录批准哈希和匹配的镜像。失败或中断的作业不会发布接受的 artifact。文件必须是绑定的常规文件，而不是符号链接/硬链接。

Loom's `receive-build PROJECT JOB` 检查这些字节是否与当前项目源代码匹配，并成功接收。它仅复制程序和可移植清单，从不复制私有计划、编译器路径、日志或审计信息。Loom 会声明、打包、验证并导出两个文件的部署。宿主独立验证并注册该部署；接收不授予执行权限。哈希不认证恶意伪造的作业目录。

### 运行时契约：file-kit-v1

现有的两文件部署格式被复用。新的精确描述组合是 `host: an-agent-file-v1`、`profile: file-kit-v1` 和 `file: { op: rw, path: /work, recursive: true }`。其他字段符合狭窄的 stdio 合规性。`/work` 是此宿主 ABI 的保留声明槽位，不涉及对机器的 literal /work 目录的访问，也不代表一个全局路径别名。执行计划记录其绑定到一个运行的私有 `work/` 目录。不要将此描述与另一个宿主进行解释。

套件启动时位于该目录。它读取 `input.txt`（一个快照，最多 8 KiB UTF-8）并写入 `output.txt`（最多 64 KiB），使用 create-or-truncate 模式。在 Linux 系统上，宿主预先创建输出 inode；`create_new`，原子替换和临时文件位于此 ABI 外。实际政策比粗略的 YAML 请求更严格：仅输出路径可写。它无法修改输入、审计、注册表、源文档或其他运行的文件。网络、模型调用和子进程仍被禁止。stdin 为空；stdout 和 stderr 保持诊断信息的 boundedness。墙限制为五秒。

在收割一个成功的进程后，宿主拒绝了一个缺失、过大、符号链接、硬链接或非常规的输出。接受的字节被复制到`artifact.txt`目录外，并在`receipt.json`中标识。用户原始文档未被自动应用。原始的stdio-only-v1权限保持不变。

为将已通过验收的产品传递至后续模型请求，需显式选择`context-export RUN artifact AUDIENCE_UUID TEXT_BYTE_BUDGET NEW_OUTPUT`。宿主在生成受限上下文视图前，会检查成功、退出/收割证据、固定路径、大小和摘要。它从不替换诊断信息或套件的可写工作副本。[上下文导出](model-services.md)和模型批准保持独立步骤；Loom 不拥有运行时上下文选择权。

### 平台和生命周期限制

孤立的Rust **build** 配置仍仅支持macOS。File-kit **执行** 在macOS和原生Linux上得到支持；其他系统不支持。Linux使用现有的Landlock/seccomp监督器，文件权限按照[Linux验证](../../platforms.md#runtime-matrix)中详细说明的固定权限设置。Linux部署需要单独构建原生程序；成功文件执行不会建立隔离编译。SPACE机器接受仍保持独立。

编译器阶段复用宿主的有限管道/取消/截止时间监督器，与一个专用进程组一起使用。领导者在进程组被信号之前保持未被回收，从而避免PGID的重复使用。在被拒绝的组上进行macOS成员信号时，遵循Codex的进程组辅助工具中所检查的方法；不会引入Codex运行时依赖或复制的模块。成员清理错误仍被视为错误。此内容覆盖了可信编译器子进程，而非对抗性setsid/double-fork作业。只有宿主直接领导的进程会被回收；子进程退出并不构成cgroup空闲的证明。Kits和测试被禁止进行fork操作。

接受/无自动回滚，不自动重试。硬宿主死亡，不可中断的内核状态和存储错误可能导致部分证据残留。保留是手动进行的。检查部分作业；使用另一个尝试的全新目的地。此切片 neither promises rollback nor expands workspace GC.

### 接受

- `cargo test -p an-agent-host --test file_job`：真实编译/测试，文件执行，外部源包含拒绝，输入不变，审计/网络/子进程拒绝，缺失/过量/链接输出，过期批准，取消，无虚假应用。
- 监督测试：编译组截止/取消，退出领导者并继承子进程管道，现有标准输入生命周期测试。
- Loom的 pinned 跨仓库 `file_job_handoff` 测试：构建 → 检查 → 审批宿主构建 → 接收 → 声明 → 包/验证 → 导出 → 注册 → 审批文件执行。两者均保持独立可构建。

### 导出调试元数据

固定编译器配方请求 `-C link-arg=-Wl,-S` 用于程序和测试二进制文件。Rust 源码跨度重映射 alone 无法消除 macOS 链接器对象文件记录中包含的绝对工具链路径。所选的原生链接器在宿主发布和哈希接受的字节之前会移除该元数据。这并不依赖于一个可失败的后链接剥离辅助程序，该程序可能引发编译器警告。消费者不需要修改接受的程序或重写其构建凭证。

此操作会移除编译器/链接器的调试路径记录；它并不有意屏蔽源代码或依赖中嵌入的私有字符串。本地计划和完整诊断信息仍为操作员数据，不应作为可移植的构建证据发布。

## 进程所有权和终止

直接子所有者在停止时缓存观察到的退出状态，显式杀死并等待，当遇到早期返回或 unwind 时尝试清理。管道工作者是作用域的；进程所有者在作用域内创建，其清理在自动 join 之前完成。所有正常的 worker join 都在错误传播之前被收集。工作者创建是失败的，普通 I/O 错误会通知 supervisor。中断的读取会被重试，而不是被误认为取消错误。如果外部 reaper 消耗了子进程（ECHILD），清理将拒绝发出可能被复用的 PID 并报告缺少确认信息。

第一个观察到的停止原因被保留。如果多个条件在同一个 poll 中首次观察到，优先级为取消、输出容量、I/O 错误、然后是截止时间。最终输出容量检查仍能捕获自然退出后的缓冲溢出，但不会覆盖先前的停止原因。

单调截止时间开始前启动。一个阻塞的OS启动不能被此同步实现中断；超时设置时间计一次，控制返回后计数。检查大约每10毫秒发生，而不是在硬实时截止时间上。没有宽容期或交互式中断协议被授予套件：宿主在取消/超时时终止单个受限工作负载。

### 证据和失败

接收器添加process.pid、process.reaped和process.scope（直接子进程）。无启动拒绝或取消具有null PID和reaped=false。PID是一个观察结果，而不是可重用进程句柄或未来PID的信号权限。遇到可恢复监督错误的启动执行被失败，而不是误标为预启动拒绝。清理错误被明确未确认；它从不标记为已应用。失败的I/O/设置可能阻止保留部分流字节；诊断不是对完整输出保留的声明。

SIGINT/SIGTERM注册所有权属于CLI，而不是宿主库。注册守护程序在部分失败、正常返回和 unwind 时移除成功安装的处理程序。取消通过正常接收/审计解决；共享分配锁在进程启动前已释放。后续取消不会撤销已解决的运行。这覆盖了套件运行命令。对于单独的HTTP模型命令的取消，见[模型取消和截止时间](../../model-services.md#cancellation-and-deadlines)。

### 限制

单独的[受限构建配方](workspace-jobs.md)为受信任的编译器/链接器子进程添加了macOS进程组作用域。它保留领导进程直到组清理完成，并在macOS拒绝组信号时检查个体成员，遵循在[Codex进程组助手](https://github.com/openai/codex/blob/2351d9e1b608e6f9d9a3699b71d7eb39ee41cfa4/codex-rs/utils/pty/src/process_group.rs)中审查过的做法。此操作不授予子进程对stdio/文件套件或测试的访问权限。

stdio 配置仍拒绝进程创建。这修复了直接子进程的所有权；它不实现任意后代的发现或进程树管理。在未来的配置中允许子进程需要一个新的审查过的终止边界，而不是此处的静默放松。

清理工作以最佳努力进行，如果操作系统拒绝 kill/wait，则无法继续。不可中断的内核状态可能延迟终止和管道连接；在这种情况下，没有用户空间包装器保证硬性清理截止时间。恐慌 unwind 清理子进程并连接工作者，但无法保证最终接收。Abort, SIGKILL, 宿主崩溃和电源中断会绕过 Rust 解构器。Linux 保留其现有的父进程死亡信号，而 macOS 在此切片中没有对应的崩溃保证。在突发宿主死亡后，部分残留的 artifact/过时的锁需要检查，而不是自动重放。

### 接受

- 自然沙盒测试验证超时、取消和输出溢出，使用 waitpid 证据表明直接子进程已被 reap，而不仅仅是状态字符串。
- 错误/ unwind 注入与阻塞输入/输出工作者验证 owner-before- scope 清理；重复终止是 idempotent。
- 实际 CLI SIGINT 和 SIGTERM 测试检查结果子进程的 PID、接收情况、应用状态、释放存储锁以及后续成功的运行。
- 预先启动取消和完整宿主截止时间测试验证 no-start 与 started/reaped 证据以及失败运行审计。

信号接受使用在原生 macOS 和 Ubuntu 运行器上可用的标准 pgrep 工具，仅用于识别测试自身 CLI 的子进程。生产环境不依赖 pgrep 或基于 shell 的进程发现。

### 审核组完成

一个退出零码且仍有剩余组成员的协调器不是完成的流程。监督者观察 peers 而保留未 reap 的领导者，记录 `group_cleanup_required`，终止拥有组并报告失败，除非已有的取消/超时提供了停止原因。这避免了仅仅因为强制清理成功而仅仅因为部分输出。单子进程配置和 OpenShell 保留其自身的现有完成合同。

审核工作区适配器此外记录了受限的 post-reap 组观察。重新和空组确认是不同的；缺失/失败的确认阻止接受、继续和擦除重放。数值 PID 是诊断证据，而非后期信号的持久处理。参见 [多 silk 执行计划](testing.md) 以获取资格和限制。

组取消也考虑了 forks 竞争第一个信号。在 reap 领导者之前，清理确认其退出并重新观察剩余的 peers，同时组身份仍被拥有。这防止了一个晚来的子进程持有继承的管道直到其自然退出。清理观察是有限制的，不授权重放或信号一个随后重用的组 ID。[压力报告](testing.md) 保留了观察到的延迟取消案例和回归/资格限制。
