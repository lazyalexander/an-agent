# 平台支持与资格认证

[English](../../platforms.md) · 中文译文，以英文为准。 · [中文目录](../README.md)

这是 an-agent 的运行时支持矩阵。Loom 拥有对应的 [作者指南和包移交矩阵](https://github.com/lazyalexander/an-loom/blob/dev-advance/docs/platforms.md)。保持所有权边界对齐；不要将运行时声明复制到每一个功能文档中。一个构建、测试跳过或清单声明并不能证明该执行边界在该机器上有效。

当前交付目标是本地，已审查的无头 spools。现有 Linux 实现和 CI 保持不变；扩展 Linux 执行、GPU/GUI 支持或添加一个后端是独立的工作。没有隐式的操作系统转换。

OpenShell 保留为可选后端；扩展暂停。其现有的适配器和失败测试在它们的固定资格范围内仍然得到支持。它不是原生 spool 生命周期的必要条件。无头描述的是一个交互模式，而不是信任：需要更强隔离的工作负载必须在一个合适的选定后端资格通过之前被拒绝。不要自动降级到原生执行或弱化声明以适应它。

## 实现边界

- 原生策略、进程所有权和平台选择在`crates/an-agent-host/src/execution/sandbox/`下实现。已审查的工作空间适配器拥有其资格谓词和现有的运行时/配置标识符。Spool生命周期、需求、发布评审和工作空间规划咨询该适配器而非独立选择一个操作系统。
- 专用文件系统适配器，如APFS快照克隆和可执行程序发布，保持其自己的系统调用/编译时边界。这不是将每一个`cfg`移动到全局平台框架或削弱文件安全性的理由。
- 域名代码、事件路由、状态选择和构件保管仍保持平台独立。它们仍然需要实际的授权和原始结算证据。一个资格标志表示资格，而不是安装执行的证明。
- `macos-native-process-v1`、`macos-native-python-v1`和现有后端/配置ID是兼容性标识。它们仍保留在manifests、receipts、fixtures和适配器验证中；这项清理不重命名它们或改变批准哈希、历史字节、发布摘要或Linux拒绝行为。

本变更中没有新的能力注册表、环境探测服务、依赖解析器或运行时协商协议。未来支持必须在相关适配器中实现并资格认证，然后反映在本矩阵中。

## 接受入口点

Python原生CLI套件使用其本地`host_qualification.py`入口辅助程序。它在创建fixtures或调用宿主之前保持原有的原生工作空间前提条件。它不执行探测、回退到另一个后端或授予执行。现有`native_state.py`不支持的平台unittest跳过；其他显式运行器拒绝不支持的启动。无论是哪种情况都不算成功运行时资格。

宿主CI矩阵在保留两个必需的job名称、所有原始命令、断言、截止日期和证据上传的情况下，选择原生工作空间车道。原生和Linux Rust检查仍运行在它们原来的车道中。直接行使操作系统系统调用的测试保留编译时测试边界。

Loom独立拥有其测试入口前提条件，并为真实包/交接测试指定一个精确的宿主版本。它不导入宿主实现代码或从测试辅助程序推断授权。当更改支持时，更新拥有适配器、本矩阵、配对Loom手off参考和相关真实接受一起。保留历史报告作为报告，而不是当前支持表格。任何不支持的车道不得重新分类为成功以通过CI。

Apple Silicon Blender Metal 的 reviewed workspace 路由已通过蒸汽机、四缸完整成片与源检查、取消及正式产物保管。图形访问须显式选择，参见[操作者配置](workspace-jobs.md)。这项资格限定于本机案例，其他 GPU、GUI 及注册式 spool 部署保持各自验收范围。

三个机械教学包的普通原生 Python 实例已接入原守护队列；蒸汽机与四缸六个阶段均完成产物验收，上下游保留固定版本引用。图形规则复用原 reviewed workspace 策略。教学操作页和原只读观测页复用同一任务状态；新一轮 Krita 原生窗口的视觉确认受锁屏阻碍，不能据打开请求认定通过。详见[守护服务](daemon.md)。
