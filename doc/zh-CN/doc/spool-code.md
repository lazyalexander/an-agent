# 轮廓内容标签：丝线和套件

[English](../../spool-code.md) · 中文译文，以英文为准。 · [中文目录](../README.md)

状态：已达成定义，修订版本3。标签描述来源和生命周期，不涉及代码责任、语言、文件扩展名、目录或权威。现有合格轮廓保持执行限制。本修订版本不实施任意运行时编辑或通用覆盖文件系统。

## 不可变基线和可变衍生品

| 内容 | 标签 | 规则 |
| --- | --- | --- |
| 所有已选发布文件，包括程序、配置、技能和AGENTS.md | 丝线 | 不可变基线；通过经过审查的开发和新发布进行更改 |
| 被 agent 修改过的基线文件工作副本 | 套件 | 分离衍生品；从选定发布中永远不覆盖 |
| 新文件、生成的程序和其他未提交的工作 | 套件 | 默认情况下由尝试所有者拥有；不自动保留或可执行 |
| 已已验收的产物和提交状态 | 分离的 custody 记录 | 明确接受/提交并保留；永远不能用擦除方式删除 |

一个位于遗留 `kit/` 目录下的文件仍然是发布中的丝线。未修改的工作副本保留 silk 标签。修改后标记为 kit，恢复原字节后仍保留修改历史。重置恢复字节；它不会将可变工作副本转换为发布。文件类型（程序、配置、指令、数据）与标签无关。一个程序不会仅仅因为实现了核心领域逻辑而成为丝线。

## 编辑和指令保护

程序和配置仅可在单独授权的工作副本中进行修改，且仅限于选定宿主配置支持的可编辑路径。基准值仍保持可用。记录拥有者实例/尝试、逻辑路径、源发布版本、基准值（如存在）以及衍生值（如存在）。新文件没有基准值。

技能指令，SKILL.md、agent.md 和 AGENTS.md 在尝试过程中受到保护。更新指令集需要经过审核的开发和新版本发布。在scratch中出现的新指令外观文件保持为惰性-kit数据：它们不能作为指令加载，不能扩大赋值范围或替换已选指令。无论其目录或命名方式如何，都应保护指令资源。一个重命名的指令包，仅因其扩展名而被视作可编辑配置，是不被允许的。

Kit 是一个标签，而非权限。给文件标注 kit 不会授予编辑、执行、依赖安装、网络访问或对另一尝试的访问权限。影响入口点、依赖项、权威或宿主策略的配置更改需要重新验证/批准；包指令无法授予宿主权限。在执行前，使用合格宿主路由绑定固定选中的字节及其有效权威。不要在字节被修改时运行代码。

## 结算、重置和收集

未被保留的 kit 只有在确认整个尝试收尾完成后，才可进行重置或 scratch 收集。未知终止边界清理和自动重试。重置影响本地工作字节，而非已执行的外部效果。不暗示任何背景收集器或自动检查点继承。

保留一个有用的套件，明确作为固定字节，并作为后续工作的输入/依赖项。艺术品的 custody 不代表执行权。晋升到 silk 需要审查、检查和一个新的不可变发布；更改标签不是发布操作。接受的产品和已提交的状态使用各自的保留和引用规则，并且能够存活于普通的 kit/scratch 收集中。

## 所有者和兼容性

域 `spool` 传递知识、指令、程序和业务接受含义。Loom 准备受限任务，记录受保护/可编辑路径，检查候选者并打包选定字节。宿主接受执行，实施授权，结算尝试，并拥有状态/制品/临时存储的保管权。后端提供隔离和终止证据；Shuttle 介于授权应用程序交互之间。成熟编码利用自身的编辑/模型循环和原生上下文。

现有 `[silk]` / `[kit]` 字段，`silk/` / `kit/` 路径，`Kit` 别名，`file-kit-v1`，`build-kit`，`kit.*` 事件和历史 Silk 通信记录 保持其线缆和解析含义。它们是兼容绑定，而非标签定义。旧版本标识和历史凭证永不重写。

当前原生配置支持通过 legacy `kit/` 槽位固定选定文件和批准跨运行工作副本更新。该限制是配置限制，而非声称只有胶水才能成为 kit。任意路径覆盖、添加可执行文件或配置槽位，以及运行时自我编辑，需要单独资格的宿主路由。新文件 kit 标签 alone 必须不绕过该限制。

## Kit 变更记录修订

未修改的工作副本保留 silk 标签。被 agent 修改后的文件标为 kit，适用于代码、skill、指令和普通文件。kit 标签描述修改来源，可信度、验收决定和回滚需求分别记录。恢复为原始字节后仍保留修改历史，`matches_baseline` 表示当前内容是否匹配基线。目录名称不决定标签，旧 `kit/` 槽位继续作为兼容绑定。指令修改仍需符合宿主的授权范围。
