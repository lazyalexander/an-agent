## 可选OpenShell虚拟机适配器

维护状态：保留此可选适配器及其失败测试；扩展暂停。当前产品路径为原生无头执行。以下历史资格认证与原生spool状态/事件/制品托管无关。缺失隔离无法授权原生回退。

`run-openshell`是现有`file-kit-v1`部署契约的宿主侧后端。它不改变核心，无需在运行时启用Loom，不安装包，不解释工作流业务逻辑。原生执行保持不变。此适配器使OpenShell **0.1.5** 在macOS上通过其VM驱动程序和Linux ARM64可执行文件成功运行。其他平台关闭，没有回退选项。

```text
Loom -> deployment (spool.yaml + Linux ARM64 program)
                       |
                       v
an-agent-host: registration / admission / input snapshot / audit
                       |
                 OpenShell adapter
                       |
        operator-owned OpenShell gateway + VM driver
                       |
             dedicated VM -> CLI kit
                       |
      bounded candidate -> confirmed VM stop -> host artifact
```

### 操作员设置和调用

安装官方匹配的OpenShell CLI、gateway和VM驱动程序，并配置一个具有认证访问权限的专用gateway。gateway的安装、凭证、基础镜像获取和容量是操作员的责任，而不是spool的权限。此适配器不下载工具或启动一个gateway。保持其配置、宿主存储和二进制文件对未授权的写入者不可见。

创建一个由操作员拥有的JSON配置文件（替换每个占位符）：

```json
{
  "cli": "/absolute/path/to/openshell",
  "cli_sha256": "<64-character SHA-256 of the installed CLI>",
  "config_home": "/absolute/path/to/isolated-config",
  "gateway": "kit-validation",
  "image": "nvcr.io/nvidia/base/ubuntu@sha256:<verified image digest>",
  "wall_seconds": 2,
  "control_seconds": 90
}
```

网关必须仅报告VM计算驱动程序。CLI和网关版本已检查；每次操作时，CLI哈希值均重新检查。这属于部署资格，而非网关的密码学认证。需提供已批准的、带有批准的签名图像，包含`/bin/sh`、`/bin/sleep`、`/bin/chmod`、`/usr/bin/python3`以及正常的系统运行路径。不挂载宿主目录。

```sh
an-agent-host register deployment host-store
an-agent-host run-openshell operator.json host-store RELEASE input.txt
an-agent-host run-openshell operator.json host-store RELEASE input.txt --execute
```

预览不提交虚拟机。宿主重用注册、不可变可执行发布、预览准入和审计。`/work`在现有声明中映射到客机 `/sandbox`；固定ABI保持 `input.txt` -> `output.txt`。
系统运行读取并客机 `/tmp` 是显式后端必要条件。没有附加提供者、转发的环境凭据或允许的网络目标。宿主仅将程序和输入快照复制到虚拟机中。
准备必须报告精确提交的文件系统策略和显式空网络策略对象。缺失、空或格式错误的策略字段将被拒绝。
签名锁定的镜像必须为隔离可信收集器提供Python 3；缺少Python将导致运行失败，无shell回退。收集器以 `O_NOFOLLOW | O_NONBLOCK` 开启，验证常规类型、一个链接和受限大小于 `fstat`，并读取相同的描述符。其源签名包含在预览中。
硬Landlock是必需的。这些设置不会阻止一个套件计算或生成其授权客机文件系统内的更多代码。

### 取消、截止日期和发布

每个调用创建一个独立、永不重启的沙箱，带有随机名称和宿主运行所有权注释。共享/重用的沙箱不被支持。
宿主在提交前记录所有权，并且每个控制请求/结果。没有自动重试创建或执行请求。

1. 验证网关，创建VM，绑定沙箱ID和运行生成。
2. 上传程序/输入并执行，使用**本地监督截止日期**。
3. 成功仅捕获一个受限UTF-8候选（最多64 KiB）。
4. 每次提交后，验证所有权，请求沙箱停止，并分别观察 `Stopped` 对于同一身份和运行生成。
5. 只有在确认停止并执行最终取消检查后，才发布成功候选。超时/取消不会触发候选检索。

SIGINT/SIGTERM设置宿主取消标志。清理使用其自身的受限截止日期，并不被该标志取消。执行截止日期**不是**保证远程计算在该时刻停止：控制平面延迟仍存在。
OpenShell CLI退出或其 `--timeout` 单独不是远程终止的证据。如果无法确认停止，状态为 `termination_unconfirmed`，而非成功或清洁取消，并且没有发布任何文件。停止原因被保留。

接受的文件是一个受限不可信快照，不是域名有效性的证明或静止整个文件系统快照。背景进程可能在捕获期间更改客机字节；它不能导致额外文件的导入。一个晚来的文件永远不会升级已失败的运行。receipt `artifact_accepted` 记录宿主发布到保留的运行目录；适配器 `candidate_eligible` 记录早期生命周期决策。这不是不可变的目录接受：`artifact-import` 目前需要原生宿主结算证据，并拒绝OpenShell运行，直到一个特定后端的宿主结算合同可用。

### 证据和恢复限制

运行目录保留输入/上下文哈希、请求/结果日志、`openshell-owner.json`、`openshell.json`、`receipt.json` 和现有审计。
receipt过程PID/reaping描述本地CLI仅。远程终止单独报告。候选内容不复制到控制日志中。
诊断可以包含路径和客机文本：将运行目录视为私有。

停止沙箱被保留用于显式操作者的检查/移除。宿主崩溃、SIGKILL、磁盘故障或不可用的网关可能导致运行状态不确定。本版本不提供持久化的 reconciliation daemon。使用所有者日志检查指定的沙箱，验证其运行注解，停止它，并确认其状态。不重启它或自动采用其输出。未声称进行磁盘回滚、事务性外部效果反转或一般性安全证明。SPACE 集成和提供者/模型路由超出本切片范围。

[本地生命周期评估](openshell.md) 检查选定后端的停止/启动实现，并提供一种自愿的冷工作区恢复测试。该测试不向生产适配器添加暂停、内存恢复、备份或重启权限。

### 验证

常规单元测试覆盖超时、候选捕获后取消、失败停止、身份替换、提交不明确和输出过大。它们验证适配器决策，而非虚拟机隔离。

自愿的实测需要已配置的网关，已构建用于 `aarch64-unknown-linux-musl` 的现有文件列表 kit，以及为该相同目标编译的 `tests/fixtures/openshell_probe.rs`。探针创建早期输出和延迟写入后代。使用绝对规范路径和新鲜的证据目录：/no_th_th

```sh
AN_OPENSHELL_PROFILE=/absolute/operator.json \
AN_OPENSHELL_EVIDENCE=/absolute/new-evidence \
AN_OPENSHELL_KIT=/absolute/file-list-linux \
AN_OPENSHELL_PROBE=/absolute/probe-linux \
cargo test -p an-agent-host --test openshell_live -- --ignored --nocapture
```

使用 `wall_seconds: 2` 使超时发生在探针的八秒延迟写入之后。
测试保留了虚拟机状态和证据不变。在超过八秒之后，一个操作员可以分别启动每个已停止的探针虚拟机，验证 `late.txt` 是否不存在，并将其再次停止；这种诊断重启不是适配器行为。

#### 记录的验收（2026-10-23）

Apple Silicon 宿主，官方 OpenShell CLI/gateway/VM 驱动 0.1.5，ARM64 Ubuntu 镜像已锁定到 digest
`7e0f726d635d440d28a7f18e6498d3bdb76c7038bd4c90a090c21eb7c9f40686`:

| 测试用例 | 宿主结果 | 远程停止确认 | 证据 |
| --- | --- | --- | --- |
| 旧的文件列表 kit，未改变的 Linux 可执行文件 | 成功 | 是 | `alpha\nbeta\n` |
| 挂着的 kit，八秒延迟的后代；两秒截止时间 | 超时 | 是 | 拒绝 |
| 同样的 kit，执行提交后取消 | 取消 | 是 | 拒绝 |

真实集成测试在 58.09 秒内完成了所有三个用例，包括虚拟机 provisioning 和 teardown。在每个延迟写入截止时间之后，单独的操作员检查会重启两个已停止的探针虚拟机：早期输出存在但 `late.txt` 不存在。两个虚拟机在检查后再次被停止。这区分了正在运行的探针和在启动前发生的取消。通过的文件列表输出 SHA-256 是 `e49c81e2d2f84e259d40e2fb8192f3bcd198b355184845d76d8f58807d0d78ee`。

此前直接使用OpenShell CLI进行的评估（不使用此适配器）观察到，在`sandbox exec --timeout`和中断本地CLI后出现延迟写入。这一观察结果就是为什么此适配器明确地停止了VM，而不是将本地进程退出与远程取消操作等同起来。这些测试是界限接受度证据，而非对任意VM逃逸或控制平面失败的证明。原始日志、本地路径和TLS材料已故意未发布。

## OpenShell本地生命周期评估

范围：已经通过资格审查的OpenShell CLI/网关/VM驱动程序**0.1.5**在Apple Silicon上，源代码修订号
`bdb956f2cd65a635f1294fccf1d138d263bf650f`。这是一项受限的后端评估，不涉及对每个OpenShell发布版本或每个libkrun功能的声称。

### 什么实际上可以被复用

| 要求 | 观察到的接口/实现 | 决策 |
| --- | --- | --- |
| 暂停准入 | 一个宿主调度决策，而不是一个计算驱动程序的RPC | 直到有真正的多阶段消费者出现 |
| 冻结运行中的虚拟机 | 选定的计算合同或CLI中没有暂停/恢复RPC | 本适配器不支持；不通过启动器信号进行模拟 |
| 挂起和恢复内存 | 选定的合同中没有内存快照/恢复RPC | 不支持；停止/启动并不等价 |
| 停止和冷重启工作区 | 后端停止保留磁盘状态；启动时重新使用新的启动认证的叠加层 | 对明确的操作员验收测试进行复用 |
| 完整虚拟机备份/恢复 | 选定的合同中没有导出/导入备份RPC | 不复制私有驱动状态，将其称为支持的备份 |
| 保留已接受的kit输出 | 存在宿主凭证、哈希值和不可变的已接受副本 | 保持这一边界；它不是整个虚拟机恢复 |

CLI 的工作负载模板描述了镜像、资源、环境和驱动配置。它们并不捕获运行机器的磁盘和内存状态。在源码中，许多“snapshot”表示资源/状态观察，而不是可恢复的虚拟机图像。

### 最小接受和责任边界

可选测试首先调用真实宿主的注册、准入、控制文件-kit 执行、确认停止和接受制品路径。只有在操作员直接请求后端重启之后，测试才会直接请求后端重启。生产 `run-openshell` 仍保持一个沙箱/运行，没有重启或自动重试。
测试重用了现有的CLI传输、受限进程监督器和请求/结果日志；引入了新的生产虚拟机API。
见证区分磁盘恢复和执行延续：

1. 确认宿主的已定沙箱ID、生成和停止状态。
2. 显式启动它；要求相同的沙箱和一个新的运行时生成。
3. 运行一个过程，写入检查点和启动身份，同步，并在十二秒后写入一个晚标记。在停止前观察准备就绪。
4. 在停止时确认停止和拒绝命令。
5. 再次启动，验证保留的检查点和制品输出，一个改变的启动ID，另一个生成和不变的有效策略。
6. 等待超过旧进程延迟；要求其晚标记不存在。
7. 在检查期间仅修改虚拟机输出；要求宿主的接受制品和原始收据保持字节一致。
8. 验证所有权并确认最终停止，保留所有证据。

这是一个合作的检查点固定，而不是数据库一致性、崩溃恢复、硬件迁移、凭证重放测试或虚拟机逃逸测试。生成旋转是可观察的；它本身并不能证明每个旧凭证都被拒绝。现有的模拟生成不匹配测试继续保护宿主的停止/接受边界。

### 运行可选测试

使用现有的[操作员设置](openshell.md)。监听TLS和虚拟机启动签名是分开的要求：配置网关的启动签名材料如OpenShell文档所述。一个健康的监听器单独是不够的。不要削弱认证以使测试通过。
当以清除环境启动网关时，显式配置其XDG配置、状态和数据目录。虚拟机启动器需要其运行时数据目录，即使网关本身成功启动。这些都是受托操作员设置，从不授予一个套件的权限。

使用规范的绝对路径，使用新的证据目录，使用已验证的摘要签名图像，并保持不变的Linux ARM64文件列表套件：/

```sh
AN_OPENSHELL_PROFILE=/absolute/operator.json \
AN_OPENSHELL_EVIDENCE=/absolute/new-recovery-evidence \
AN_OPENSHELL_KIT=/absolute/file-list-linux \
cargo test -p an-agent-host --lib real_workspace_cold_restart -- --ignored --nocapture
```

图像必须提供`cat`、`sync`、`sleep`和`/bin/sh`，并满足现有的适配器要求。测试保持停止的虚拟机和私有证据；它从不删除无关的沙箱或覆盖之前的运行。检查`cold-recovery.json`和控制日志。初始宿主运行失败时，保留正常的宿主凭证。不发布配置、机器身份、网关凭证或原始的guest/control日志。

在OpenShell 0.1.5的历史资格审查中观察到磁盘持久性和更改了启动身份，而非内存恢复。生产重启仍不被支持。完整的历史结果可在Git历史中找到。
