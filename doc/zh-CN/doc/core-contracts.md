# 核心身份与记录合约

[English](../../core-contracts.md) · 中文译文，以英文为准。 · [中文目录](../README.md)

## 交付权限与落地证据

交付准入已经将注册摘要和生成、代理化身以及挂载的卷轴实例绑定。发布现在重新验证所有四个要素。更改注册然后恢复相同的字节不会恢复旧的授权：其生成是不同的。相同的连续注册保持其生成，并且不会使回复失效。

### 发布边界

在节拍体返回后，或代理体发出其最终语句后，验证和卷轴注释/意图准入将与注册更改、卸载和释放共享现有的监督互斥锁。检查和发布是一个临界区。相同的围栏覆盖一个停止注释。没有用户体、钩子、模型调用或外部回调在此临界区中执行。本地磁带I/O仍保留在其中以保持顺序。

一个过时的交付在体已经被调用时，在中断交付错误中写入`delivery_stale`审计证据并返回`ReviewStale`；这不是体失败，也不会自动卸载、重试或重新安排该体。先前有效的模型观察结果仍被保留。在钩子之后可能会运行任意宿主代码，因此在这些钩子之后再次提供/分发验证回复。在撤销之前的发布仍保留在历史记录中；之后的检查无法删除它。

### 中断批次和生命周期写入

在调用一个投递批次之前，代理磁带记录一个仅用于审计的
`delivery_batch` 开始。一个完成的批次记录 `settled`。一个中断的批次
返回 `DeliveryInterrupted`: `ready` 保留先前承认的、经过钩检查的结果，
`withheld` 保留任何未能通过最终关卡发布的回复，而 `source`
说明失败原因。就绪并不意味着已应用；在显式协调之前必须再次检查其权限。
被扣留的回复绝不能被执行。
包含的宿主泵在不落地部分结果的情况下返回此错误。
一个没有结算围栏的开始，既调度又提供该事件给该代理，包括在会话恢复之后。
一个失败的写入也会在内存中围栏该事件，因为失败的同步可能会使完整行可见。
一个恢复的实例拒绝所有先前实例的批次，包括已完成的批次；安排一个新的
事件用于新的工作。它从不自动重放一个主体或模型调用。仅对显式请求的新工作安排一个不同的事件。
围栏是保守的；没有自动部分批次恢复的API。

打开和恢复保持座位本地，直到生命周期注释变得持久，并在失败时放弃
已安排的监督。完成在撤销权限之前持久化 `finish_pending`。随后的证据失败会使完成的代理处于一种状态：新的节拍和释放被拒绝，但完成可以使用其原始结论和
关闭请求重试。被撤销的批准绝不会被恢复以补偿IO。
记录器生成使用一个待处理意图和一个本地座位；失败的清理围栏新的生成。
记录器释放持久化意图，放弃座位和取消租赁，然后放弃工作区并记录完成。失败的清理是 `ReleasePending`
且只能通过释放继续；磁带恢复将其视为已经退休。
工作区保留退休清理的身份，直到卸载日志成功，
因此重试不能静默跳过失败的日志写入并重新激活工作者。
这些是显式的可恢复转换，而不是对外部效果的原子事务或对任意存储损坏的保证。

### 宿主边界

`SpoolReply` 保留私有准入事实。宿主在执行意图前会调用 `validate_reply`。包含的泵会检查每个 Utter 和 Raise，CLI、构建和模型输出路径会在执行其被允许的操作或发布响应产物前进行检查。这些事实是内存中的授权上下文，而不是签名可转让令牌或新的持久重放格式。调用者必须通过交付获取回复，而不是构造结构字面量。

`applied` 记录宿主关于某事已经落地的声明；它不是执行外部效果的 API。它在监督锁的监督下重新验证。当前声明保留 `applied` 标签。过期声明会将其原始事实、spool-note 引用、宿主注释和原因写入 `applied_stale`，然后返回错误。证据写入失败会传播；不会自动重试或合成成功声明。泵会记录在撤销停止部分执行的回复时完成的意图数量。

预检不是一个与任意应用具有原子性的事务。撤销可能在检查之后或在 sink 回调期间发生。已经完成的效果无法由核心回滚：宿主必须保留/报告这些效果，停止剩余的工作，并在需要时使用其自身的版本检查或事务边界。此切片不引入应用特定的回滚、全局外部操作锁或跨进程工作区协调。

### 恢复与验证

重新打开的会话具有新的实例，重新挂载具有新的挂载 ID。保留的旧回复无法与这些新身份进行确认，即使注册字节未改变。需要全新的交付；旧磁带历史和模型 blob 仍可读，不会被重写到新的授权中。

测试覆盖了注册替换期间的阻塞节拍、模型完成后的替换、后钩撤销、相同与 ABA 注册、缺失事实、重新打开/重新挂载、失败的落地证据写入，以及一个真实宿主泵，其 sink 在 Utter 和 Raise 之间撤销权限。后者会保留可见效果和部分过期声明，同时拒绝剩余的 Raise。

## 磁带写入者所有权

`JsonlStore::open` 在返回前获取了磁带上的非阻塞独占标准库文件锁。所有权持续到存储被释放为止。第二个独立句柄在扫描前返回 `StoreError::WriterBusy`，用于保留序列、追加或修复。其他锁错误会传播；没有未锁定的回退或自动重试。不需要新的运行时依赖。

该锁存在于打开的磁带文件上，而不是可移除的锁标记。符号链接和硬链接别名指向同一个被锁定的文件。读取、追加和截断使用的是同一个描述符。现有的实例互斥锁仍通过共享的 `Arc<JsonlStore>` 串行化操作。独立的磁带保持独立。

### 恢复和失败语义

现在打开会立即创建磁带，即使在第一次事件之前。成功的打开不会验证或修复事件内容；第一次读取/追加操作会在独占所有权下执行此操作。事件模式和旧格式解析保持不变。

`read_all` 是一个具有修复权限的所有者操作，而不是只读观察者。此切片中没有独立的只读存储 API。实时检查应使用拥有存储/控制的事件 API。会话恢复和记录器恢复必须先释放旧的所有者；它们不能打开第二个具有修复能力的句柄。任何保留的代理/存储引用在释放座位后仍会保留锁。

追加错误会使得缓存的下一个序列失效。在同步错误后保留的完整记录会在下一次显式操作或重新打开时消耗其序列；一个不完整的最后行将遵循现有的隔离路径。API 不会重试操作，也不保证追加错误意味着没有记录任何内容。

修复在截断磁带之前会同步隔离证据。截断前发生故障可能会在后续恢复时重复证据，但不能丢失证据。截断后发生故障可能导致同步结果不确定；重新打开扫描实际保留的磁带。失败的读取/修复操作也会使序列缓存失效，因此后续的追加操作无法绕过未完成的修复。错误永远不会释放活存储的所有权。进程退出会释放操作系统锁，但不会清理过期标记；下一个所有者会从保留的事件中继续。

### 边界和验证

这是协作的宿主拥有的存储协调，而不是一个沙箱，用来对抗忽略建议锁或删除/替换已拥有磁带的进程。在磁带文件的所有者仍然存活时，不要替换或删除磁带文件。网络文件系统不被支持；不支持的锁定会直接失败。测试的目标是原生的 macOS 和 Linux，不是每一个文件系统或操作系统。不声明硬件断电的合格性。

测试保留现有的共享-Arc 并发性和传统/损坏尾部的覆盖，并添加独立句柄/线程、路径别名、一个真实的 `AgentControl` 恢复、带和不带重新打开的追加/修复故障点，以及独立进程的竞争。一个进程在持有部分写入的尾部时被终止；竞争者必须保持其不变，而一个新的进程必须将其隔离并继续序列。宿主进程监督测试模块仅启动其自身的测试可执行文件。核心拥有锁和进程内故障测试；现有的宿主边界拥有子进程创建和清理。架构允许和基线保持不变。

## 环境输入身份

`Workspace` 存储宿主事实。在 `log.jsonl` 中的环境生成会选择不可变的 Markdown 字节在 `env/<sha256>`。`env.md` 是一个可替换的投影用于检查，而不是模型输入的来源。外部编辑器必须通过 `put_env` 提交其文本；编辑 `env.md` 不会创建一个生成，其内容在重新打开时会被替换。

### 写入和恢复协议

1. 将新字节写入一个唯一的待定文件，同步它，原子性地发布哈希路径而不替换现有 blob，并在 Unix 系统上同步 blob 目录。现有 blob 必须经过验证后才能被重用。
2. 追加生成记录并同步日志。成功日志同步是已确认的生成提交点。
3. 从选定的已提交 blob 构建一个唯一的投影文件，同步它，将其重命名为 `env.md`，并在 Unix 系统上同步工作目录。

投影错误返回 `EnvProjection` 并附带选定的生成 ID。日志可能已经包含新的生成，因此错误并不意味着回滚。`cite` 仍可以从其验证的 blob 返回该生成。重新打开会重建投影而不追加另一个生成。重复相同的命名写入也会验证 blob，同步保留的日志并修复当前投影，而不会重复生成或回退到旧的名称。

日志写入/同步失败具有不确定的提交结果。可能恢复完整的保留记录；缺失或不完整的记录不得从 `env.md` 或孤儿 blob 推断得出。重新打开会在返回前同步保留的日志。未终止或格式错误的日志会被拒绝并保持原样供检查。没有自动截断、回滚、重试或孤儿文件收集。

### 读取合同

`cite` 从日志中选择最新的环境生成，读取其 blob，验证 SHA-256 并解码 UTF-8。缺失的哈希、无效的路径、缺失或无法读取的 blob、摘要不匹配和无效的 UTF-8 会拒绝引用。它从不会用空字符串代替失败的读取。如果没有环境生成，引用将没有环境 ID/哈希并有意为空文本。`env_bytes` 也会验证请求的 blob 的哈希，包括历史 blob。

仅空工作区可以初始化一个新的日志。非空工作区如果缺少日志将被拒绝；打开它不能静默擦除其生成历史。旧的以换行符结尾的记录仍然可读，包括没有`name`的记录。不会执行日志或 blob 的迁移。模型输入组装已经传播了引用错误，因此无效的环境证据会阻止提供者的调用。

工作区仍然属于宿主所有。其现有的互斥锁协调一个实例；此切片不会添加跨进程写入排除或防止恶意进程重写账本。不可变的发布意味着此 API 从不覆盖现有的 blob；引用独立验证读取的字节。配置和注册负载合约保持不变。

### 证据

`workspace/env_tests.rs` 覆盖了以前的 live-file-before-log 崩溃状态、缺失/篡改的投影、孤立的待处理文件、损坏/缺失/不可读的 blob、无效的元数据/UTF-8、缺失/损坏的日志、命名写入的幂等性，以及从保留文件重新打开。每个实例有 11 个仅用于测试的 I/O 故障点，用于测试 blob 写入/同步/发布、目录同步、日志打开/写入/同步以及投影写入/同步/重命名。每个故障必须留下匹配的引用或拒绝；重新打开必须从保留的权威文件中恢复。

一个真实的 `AgentControl` 回归证明损坏的环境字节会阻止模型调用。这些是确定性的 I/O 故障和持久化状态恢复测试，而不是硬件断电的资格测试。文件系统持久性仍然取决于平台遵守同步操作。
