# 原生工作空间事件

[English](../../native-events.md) · 中文译文，以英文为准。 · [中文目录](../README.md)

状态：受限，显式无头交付在[资格原生工作空间后端](platforms.md)下。已验收的输出可以成为工作空间事实，激活一个已批准的接收者，并在正式接受后产生因果结果事件。这不是一个业务图引擎，后台监听器，低延迟通道或任意代理沙箱。

业务分支、循环、委托选择和结果解释仍保留在silk/kit中。宿主路由事实并强制身份、权限和所有权。事件和订阅不创建执行权限。子代理是一个角色，而不是为每个工具调用创建另一个spool的要求。Shuttle保持单独授权的桥梁；此切片不声称GUI执行权限。

## 发布与工作空间契约

原生v3保留v2的要求，并添加一个必需的严格`events`对象：

```json
{"consumes":["artifact.accepted"],"produces":["artifact.accepted"]}
```

每个数组可以为空，也可以包含一个支持的事件名称。未知名称、重复项和未知字段均被拒绝。V1/v2 无法携带此对象；其字节和普通行为保持兼容。较旧的宿主拒绝 v3。角色描述接口，而非对等访问、订阅、模型服务或网络授权。已审查的 macOS 政策和一个输入配置文件适用。可选的 v3 [二进制产品和运营商选择的 Python](native-spool.md) 使用相同的交付/确认协议。V1/v2 和现有文本包保持不变。本地控制存储仍对同用户篡改保持信任。哈希绑定字节和身份，而非发布者认证或远程信任协议。

一个事件工作区是一个宿主拥有的私有目录，与实例分离。`facts/` 使用核心 `Workspace` 配置快照和追加只读事件日志；没有新的日志引擎或对 Loom 的运行时依赖。原生订阅绑定将现有的冻结-接收者/意图/确认纪律适配到原生 ABI，而非模拟可信内核 `SpoolBeat` 体或将遗留文件实例凭证视为可替换。

```text
spool-events-init NEW_WORKSPACE
spool-events-show WORKSPACE
spool-event-subscribe WORKSPACE NAME ROUTE_JSON [--approve HASH]
spool-event-publish WORKSPACE INSTANCE RUN OUTPUT [--approve HASH]
spool-event-deliver WORKSPACE EVENT_DIGEST NAME [--approve HASH]
spool-accept TARGET DELIVERY_RUN [--approve HASH]
spool-event-complete WORKSPACE EVENT_DIGEST NAME [--approve HASH]
spool-event-revoke WORKSPACE NAME [--approve HASH]
```

所有命令使用 `an-agent-host`。初始化创建不执行授权。预览操作在批准前精确计划。交付预览可能准备一个受限的原生配置文件，但不会创建交付意图或执行尝试。
对于v3版本声明单独状态输入，交付额外需要 `--state REVISION`。[数据/状态契约](../../native-state.md#independent-business-data-and-state) 与事件的业务制品独立绑定。交付身份不随状态改变，因此另一个选择不能强制第二次尝试。
操作员选择精确的事件/订阅进行分发；没有自动发现、全局游标、递归排水或守护进程。
操作员拥有的路由JSON具有严格的schema `an-native-artifact-route-v1`，源和目标实例路径在 `source`/`target`，声明的源输出 `output`，声明的接收者输出 `result`，以及 `wall_seconds`。宿主绑定精确实例/发布身份和接收者控制生成。源必须声明生产；接收者必须声明消费和结果生产。
实例必须是唯一非嵌套目录。订阅是静态不可变的：名称不能用于不同绑定。路由配置中不接受谓词、脚本、分支或循环。

## 交付与消费证据

发布验证原生终止、完整接受和精确保留的制品字节/溯源信息。原始文件名、失败运行和退出状态单独无法发布事实。事件携带元数据和固定引用，不包含完整文件、提示或代理日志。稳定的事件摘要绑定工作区、生产者、运行、输出修订和可选因果交付。重复发布确认相同事实，不附加另一事件。撕裂或重复日志记录不被静默修复。

一个交付由工作区、精确事件和不可变订阅标识。不同明确批准的订阅是不同交付。一个独占意图绑定原生启动计划，前提是在接收者操作锁和工作区准入锁下。工作区锁在进程执行前释放；其他工作区操作仍可用。实际输入快照通过现有原生监督者和监护人绑定制品修订。编辑的套件、更改的代次和撤销的订阅无效准入。

意图是准入线性化点。准入后撤销不声称已准入进程已停止；使用运行CLI的现有SIGINT/SIGTERM取消。撤销限制未来准入和新自动消费确认。这不是瞬时进程生成撤销保证。卸载/重新加载改变实例身份，不继承路由。

接收事件和成功退出不是消费。在明确 `spool-accept` 后，完成验证精确事件绑定的启动、接受输出及其溯源信息，发布声明结果事件，然后记录确认。它不提交领域状态，不发明业务结果。结果事件保留其进入交付身份用于因果诊断。暂停/恢复代次限制新启动，不解决已准入接受工作。完成在准入暂停或实例卸载期间仍可用，前提是其身份/证据和订阅有效。

## 范围与资格

第一个工作区允许512条日志记录、16个静态订阅和128个交付槽位；原生实例/运行和文本-制品限制保持不变；显式声明的字节制品保留原有的8 MiB绑定。这是本地背压的限制，而不是可扩展的代理或磁盘配额。未来通道需要单独的授权、生命周期围栏和测量的背压；原始高频率样本必须不能强制通过此fsync-backed事件日志或磁带。

宿主Rust测试覆盖接口兼容性和日志故障窗口。真实macOS Python验收测试覆盖两个丝线版本，新版本发布后修复旧输入，缺失/错误批准、过期/撤销/外来的身份、重复交付、丢失确认、取消和缺失外观结果。缺失记录测试在已知执行后注入证据丢失，而不是任意崩溃或电源丢失恢复。Loom单独验证实际v3打包和交接。不引入模型、GUI、新后端或业务流程解释器。

批准的CLI交付运行在独立的原生尝试监督下进行。预览识别接收者在`plan.route.target.root`和运行在`plan.context.delivery`。显式有限列表或队列调度也绑定其父节点在启动计划中。客户端退出不授予新交付，也不承认产品。见[routed ownership and controls](../../session-and-retention.md#routed-execution-ownership)。

## 交付库存和前景监控

`spool-events-pending WORKSPACE`列出匹配事件/订阅对，不准备运行。行保留精确的工作区/事件/订阅/交付身份和准入拒绝。阶段区分`awaiting-authorization`、`blocked`、`running-or-unconfirmed`、`settled-unsuccessful`、`awaiting-acceptance`、`awaiting-confirmation`、`needs-reconciliation`和验证过的`consumed`。未确认终止被有意不简单标记为运行。一个已验收的输出没有确认不被消耗，包括在丢失确认注入后。一个撤销的路由仍可有被接受或消耗的交付；准入拒绝和交付证据是不同的字段。

`spool-events-watch WORKSPACE SECONDS INTERVAL_MS` 前景中对库存进行轮询，并发出以换行分隔的 JSON：初始快照、变更快照，然后是 `an-native-event-watch-stopped-v1` 总结。边界为 1..3600 秒和 100..5000 毫秒。每次快照后 stdout 会被刷新。SIGINT 或 SIGTERM 停止观察，原因为 `cancelled`；截止时间停止，原因为 `deadline`。独立运行的交付不会被停止。缺失或无效的证据和输出失败会结束命令，不进行静默重试。重启监控器会再次读取持久化证据，并且不会重新执行工作。不存在持久化游标或承诺在轮询之间输出所有瞬态阶段。现有工作区/交付边界仍然适用；监控器用于受限本地操作，而不是高频事件通道。

两个命令都是观察型的：它们不接受批准、选择状态、创建交付意图、确认 nothing、收集 nothing 并授予 no execution。使用现有的显式交付预览/批准用于准入，`--state REVISION` 其中需要，显式接受和完成用于保管，以及现有的订阅撤销用于新交付控制。没有自动状态选择、守护进程、批量授权或业务图被引入。监控器失败不是 reclaim 的权限，观察不是跨并发变化实例证据的权威事务。

观察使用严格的、受限的内存副本工作区日志。待处理、显示和监视不获取 `host.lock`，初始化工作区文件，修复环境投影或同步写入。在一次观察内所有路由/控制/历史检查都使用该固定日志。添加的 `observation` 字段包含其哈希和 `log_unchanged_at_end`：false 表示在扫描期间工作区或日志发生了变化。它不主张外部实例/撤销证据是原子的，即使为 true。更改的视图不会授予任何操作；修改 API 仍然获取原始锁并重新验证精确权限/当前性。破损或格式错误的日志在关闭时失败，不发出伪造的空/完整视图或重试。

真实事件 CLI 接受资格验证了待处理/已接受/已消耗和阻塞行，监控而实际头less 交付持有实例锁， revoked 后的证据变化，观察取消但执行取消未取消，截止时间退出，以及监控器重启但缺少结果证据，且不创建另一个尝试。Rust 测试覆盖破损日志和输出故障、冻结视图当前性、只读句柄和观察期间持有写锁。`native_monitor.py` 然后运行 144 个不同批准的撤销，0/1/4 观察者跨 2/8 事件和 12 路径。它检查每个修改和观察者结果、投影身份和观察者锁/写时间事件。没有失败的命令会被重试，原始事件测试时间保持不变。

在本地调试宿主上，原始矩阵拒绝了 48/144 控制和 14/20 观察退出非零状态。修订矩阵完成了 144/144 控制和所有 20 观察；控制中各单元的中位数为 24.79–26.20 毫秒。单观察者原始扫描持有控制锁，中位数为 199.86/860.94 毫秒（2/8 事件）；新观察者从未获取它。这些是小的合成、温暖的本地样本，带有诊断开销，而不是延迟 SLA 或生产失败概率。原始四个观察者/8 事件单元没有控制失败，因为所有其观察者都已死亡；观察者生存是独立的接受条件。

## 有限批准的分发

`spool-events-dispatch WORKSPACE REQUEST_JSON [--approve HASH]` 选择一个有限的现有构件事件列表。它不监听未来事件或跟踪结果事件。严格请求：

```json
{
  "schema": "an-native-event-dispatch-request-v1",
  "name": "reviewed-batch",
  "entries": [
    {
      "event": "FULL_EVENT_DIGEST",
      "subscription": "counter",
      "state_revision": "FULL_COMMITTED_STATE_DIGEST"
    }
  ]
}
```

选择1到16个唯一的事件/订阅对；对于无状态的条目，省略`state_revision`。一个不同的状态不能创建第二个交付身份。预览准备现有的受限运行配置文件，但不启动任何东西。一个批准绑定工作区、有序选择和每一个现有的交付/启动计划，包括状态、代码、目标身份/生成和运行时输入。不接受通配符、最新状态别名、未来事件授权或隐式的状态链。每个条目在准入时仍然重新验证正常的交付批准。一个更改/撤销的目标或修改的套件不能继承之前的授权。

一个独占持久化分发意图在任何条目尝试之前被记录。条目按顺序运行，每个返回的结果在选择下一个之前被持久化记录。只有成功的结果且已确认终止才能允许下一个选择。任何拒绝、失败、不确定结果或账本写入错误会停止批次；未知的工作不会被重试。一个工作区允许32个分发身份。这些是保留的证据，而不是可回收的工作队列。

对于此命令，**SIGTERM 会在当前选中项完成之后停止选择**，而 **SIGINT 会通过其现有的监督程序请求取消，并阻止进一步的选择**。其他命令保持其原有的信号含义。停止并不意味着已选项的立即撤销。取消本身并不证明终止；在任何接受或收集之前，应检查保留的原生运行凭证。进程消失或缺失的批次摘要无法授权任何操作。此切片中没有跨进程的暂停/恢复服务或并行任务池。

`spool-events-dispatch-show WORKSPACE NAME` 会观察保留的意图/入口/结果记录，但不会执行这些记录。重复一个已记录的分发也会观察到它：它永远不会恢复剩余的入口，即使它干净地停止了。一个不完整的意图、丢失的入口记录或缺失的最终摘要仍然被封锁/不确定。选择一个新的批次名称不会绕过现有的事件/订阅交付封锁。在干净停止后，仍未被承认的工作，需明确审查一个新鲜的有限选择；不要重新发送未知的交付。没有自动重试或恢复的命令提供。

调度成功意味着其选定的执行已完成并确认终止，**不**表示产品已被接受或事件已消费。接受、检查点比较与交换、事件完成和清理等工作仍为独立的宿主操作。多个条目可能明确消费相同的检查点，因此后续状态提交可能产生冲突；宿主不合并或重新基线其业务状态。Loom 包含相同的现有接口，获得不了调度器或运行时的授权。

实装 macOS 非交互式接受覆盖了精确的状态/数据结果、过时的提交拒绝、错误/更改的批准、优雅停止、带有确认的取消、执行过程中被阻断的清理、保留的状态/产品、执行后实际日志写入失败、不完整的意图和缺少接收/摘要观察无重放。证据丢失注入遵循已知的执行流程；它不是任意进程终止或电源失效恢复的声明。

## 订阅准入暂停和恢复

`spool-event-pause WORKSPACE NAME [--approve HASH]` 和 `spool-event-resume WORKSPACE NAME [--approve HASH]` 控制一个已存在的不可变订阅的准入。两者预览版本并绑定其批准时的精确先前控制生成。重复一个过渡或使用旧的批准将被拒绝；请检查 `spool-events-show` 以查看当前模式/生成。
恢复验证了相同的加载目标身份和 round-control 生成；它不能重新绑定已重新加载的实例或修复过时的路由。撤销保留永久性，并且 neither 操作可以撤销它。

暂停不发出运行过程的信号，接受产品，修改 checkpoint HEAD 或阻止已批准工作的显式完成。它在现有工作区锁下封存新的准入。恢复启用新的审核，从不重用预暂停批准：每个后续交付计划绑定当前控制生成，且准入会再次在该锁下检查。交付身份保持工作区/事件/订阅；控制过渡不能为同一对创建另一个尝试。一个有限的调度跨越暂停或暂停/恢复将停在下一个被拒绝的准入。重复记录的批次不会恢复它。尚未批准的工作需要重新选择一个新鲜的有限集合和批准；未知工作仍被封存。

控制记录使用现有的不可变工作区配置快照和日志，包含前驱绑定和最多每订阅 32 个过渡，不超过现有 512 条记录。过渡快照和日志在成功报告前同步。缺失快照和重复、重新排序或修改的已提交控制记录将被拒绝。一个错误可能留下一个已提交的过渡；请检查而非自动重试。绑定 16 个订阅的路由声明，而非控制记录。

首次使用显式升级工作区元数据从 `an-native-event-workspace-v1` 到 `an-native-event-workspace-v2`。它保留工作区身份、路由、事件事实和历史交付记录。V1 工作区无控制仍保留其原有格式和预控制交付批准形状。早期宿主在打开时拒绝 v2 而不是忽略暂停记录。不同时运行升级工作区和旧宿主；混合宿主版本和文件系统回滚不被允许。在元数据升级和控制提交之间发生崩溃可能使 v2 无过渡；单独的元数据不证明暂停已完成。未提供自动下放或历史记录重写。

待处理/监控库存包括订阅控制和准入拒绝。它仍然不授予执行或收集。真实无头接受涵盖直接和批量准入的暂停/恢复，预暂停批准的拒绝，不变的交付身份，运行中的批量暂停，暂停期间的显式托管，恢复后无批量重播和永久拒绝。本地资格也调用先前宿主二进制验证 v2 拒绝；CI 检查 v2 标志和当前宿主合同而不构建第二个宿主。

## 显式完成总结重建

`spool-events-dispatch-reconcile WORKSPACE NAME [--approve HASH]` 仅重建了一个缺失的已完成摘要。每个选定的条目必须保留其原始批次绑定记录、准确的交付/开始计划以及与确认终止匹配的成功的原生接收证明。预览是无效的；批准绑定所有那些证明和确定性的摘要。冲突的摘要从不会被覆盖。缺失的条目/开始/结果证据、取消执行和部分或停止的批次拒绝。重复重建相同的摘要无效。没有进程运行，没有批次恢复，也没有产品/状态被接受或提交。
## 明确接收顺序

`spool-event-replace WORKSPACE OLD_NAME NEW_NAME ROUTE_JSON [--approve HASH]` 重用现有的严格 `an-native-artifact-route-v1` 请求格式。生产者、事件类型和源输出保持不变。选择一个新鲜的订阅名称和一个已更改的接收者身份/生成或结果槽。预览不授予执行，批准绑定两个路由，旧控制生成和一个固定的工作空间日志切口。任何中间日志发布改变批准；重新预览显式而不是自动重试。
一个不可变的后继配置提交淘汰旧的接纳。它不重写旧的路由，移动一个运行，取消执行，迁移状态或接受输出。已经接纳的工作保持其原始交付身份，可能通过旧路由显式接受、提交和完成。保留旧实例目录/证据以确保该 custody。旧待处理单/批次批准被拒绝，退役接纳无法通过控制命令恢复。撤销一个后继不会重新激活其前继。
