# Weaver 与独立 spool 开发

[English](../../weaver.md) · 中文译文，以英文为准。 · [中文目录](../README.md)

Weaver 是一个可选的领域任务准备者和候选评审者，通过 Loom 暴露出来，以可替换的 harness 适配器形式存在。领域需求和测试保留在项目中。Loom 负责开发基线、检查和打包；宿主拥有运行时权限、监督、上下文访问和接受状态/产品。

一个 spool 可以暴露自己的 CLI 用于零挂载开发，无需代理。独立检查和离线打包并不意味着沙箱化、终止证据或宿主接受。不要将本地成功视为宿主接收。正式的平台管理代理必须在代理下被接纳和激活：选定的发布版本和实例、有效的授权、监督尝试和接受。当前的原生路径提供加载加上单独批准的启动；这并不声称是一个通用的代理激活注册表。仅加载并不赋予执行权限。一个公共可执行文件仍可以由其所有者独立运行。

选择精确的领域材料，保留来源信息，并区分原始规则与假设。开发人员在将规范发送到编码工具之前，需审查规范和接受合同。更改这些选定的字节需要一个新的审查/任务。规范批准并不赋予执行权限，也不允许将私有材料发送给提供方。独立模型/提供方和执行批准仍由宿主负责，当宿主被使用时。

宿主不评估领域真实性。Weaver 提出规则和评审发现；开发人员解决歧义。现有的 kit-proposal 插槽仅允许有限的编辑，不是 Weaver 的准备者。钩子不能扩大授权。外部 harness 保留自己的上下文/磁带；选定的请求、代码和边界证据无需导入其私有会话即可满足。

遵循 Loom 侧的 Weaver 合约和合格示例。不特定于领域的解析器、模型循环、知识库服务或新后端不应包含在核心中。
