# 原生状态和发布变更

[English](../../native-state.md) · 中文译文，以英文为准。 · [中文目录](../README.md)

## 原生spools的显式状态

状态：已通过审核的无头macOS shell和选定的Python配置文件。此版本适配现有的artifact修订存储，固定输入工作空间快照，接受输出证据和实例级锁。它不重用遗留的文件-kit实例注册、解释业务状态、添加后端或更改发布格式。
现有原生v1/v2包和普通 `spool-start` 仍保持兼容。

### 所有权和使用

spool作者定义一个透明的UTF-8状态文档，其域验证和一个声明的输出承载下一个状态。Loom包这些域文件和现有的输出声明。an-agent拥有显式的选择、版本控制、执行授权和序列化发布。一个状态版本不是进程图像、自动恢复指令或外部效果的授权。

```text
an-agent-host spool-state-init INSTANCE STATE_OUTPUT INITIAL_FILE [--registered] [--approve HASH]
an-agent-host spool-state-show INSTANCE [REVISION]
an-agent-host spool-start-state INSTANCE RUN REVISION SECONDS [--approve HASH]
an-agent-host spool-accept INSTANCE RUN [--approve HASH]
an-agent-host spool-state-commit INSTANCE EXPECTED_REVISION RUN [--registered] [--approve HASH]
```

初始化、启动、接受和提交需要各自的预览和精确批准。
预览始终不执行任何过程或更改HEAD。初始状态是显式地由操作员种子生成的，不被声称是之前接受过的运行状态。初始化选择一个已有的输出槽；未声明的输出被拒绝。状态使用现有的64 KiB文本修订限制；声明的二进制输出不能作为状态选择。

遗留的仅状态模式有一个输入：`AN_SPOOL_INPUT`是选定的状态文档。以下的自愿v3组合将业务数据与该状态分开。选定的代码和状态输入必须在现有的原生输入命名规则下保持独立的快照基名。

`spool-state-show`报告HEAD和一个固定已提交的选择，包括其目录/路径/绑定，而不Dump状态内容。新选择需要开放的准入和一个在HEAD及其最近1023个祖先中的已提交版本。一个更旧的已提交版本可能被显式评估，但不能替换一个更新的HEAD。

启动记录精确的状态修订、选定代码的哈希值和尝试输入映射。现有的工作区机制将该不可变的修订读入一个尝试私有读取只读快照。工作负载不能读取或写入状态目录、HEAD、批准记录或兄弟尝试。一个平铺的`spool-start`，其字节完全相同，不是状态绑定的运行，不能通过此API提交。

### 独立的业务数据和状态

原生v3要求可能声明`state_input`，一个可移植的快照文件名，与`inputs`业务数据槽以及所有代码基名不同。该字段在遗留版本中缺失；其序列化合同和行为保持不变。一个更旧的宿主拒绝该新字段，而不是将状态映射到业务数据中。没有新增的VM、域解析器或状态格式。

对于此自愿的条目，`AN_SPOOL_INPUT`命名一个固定的业务产物，`AN_SPOOL_STATE`命名一个显式选择的已提交检查点。两者都是尝试私有读取只读拷贝，即使它们的目录存储着`content.txt`，其声明的文件名也不同。代码、业务数据和状态共享拥有spool尝试的现有监督和权力边界。平铺或遗留状态仅模式启动时拒绝此自愿条目；状态必须显式指定，不能继承或从HEAD猜测。

```text
spool-start-data-state INSTANCE RUN SELECTION_JSON SECONDS [--approve HASH]
spool-supervisor start-data-state INSTANCE RUN SELECTION_JSON SECONDS [--approve HASH]
spool-event-deliver WORKSPACE EVENT SUBSCRIPTION --state REVISION [--approve HASH]
```

所有命令使用 an-agent-host。严格的运算符选择 JSON 是：

```json
{"schema":"an-native-data-state-v1","data":{"catalog":"/selected/catalog","revision":"EXACT_DATA_REVISION"},"state_revision":"EXACT_COMMITTED_STATE_REVISION"}
```

宿主验证了两个目录/修订版本，并将完整的引用绑定到启动批准和工作区输入库存中。工作负载接收文件，而不是选择器、目录访问或授权记录。直接选择验证所选对象的字节/来源；它不认证其作者或推导生产者的业务成功。事件路径仍然需要正式生产者的接受。直接运行的第一-preview冻结其选择；更改它需要一个全新的运行身份。事件适配器保留一个事件/订阅的交付身份：一个显式的状态变化不能创建另一个执行。一个已存在的交付上不同的状态被拒绝；省略--state只能观察一个已有的交付，而不是启动一个状态化的。在准入之前，一个准备好的事件运行也冻结其选择；更改它需要一个新明确授权的订阅，而不是覆盖已准备的配置文件。未知结果被围栏，没有自动重试。

显式的监督入口使用相同的选择，并保留过程所有权在客户端丢失后。其持久请求存储已解析的绑定；工作节点不重新读取选择JSON。它在执行前重新检查准入和精确的原生计划，因此废弃/不可用的输入拒绝而不是选择替换。参见[尝试监督](../../session-and-retention.md#independent-attempt-supervisor)。

状态提交验证业务/状态输入绑定的精确有序对，接受的状态输出和预期的检查点HEAD。一个后来的业务版本永远不会改变这个对；一个较旧的已提交状态可能被评估，但其输出不能覆盖一个较新的HEAD。接受、状态提交和事件消费完成是分开的显式操作。完成确认已验收的输出，而不是隐式的检查点提升；调用者决定何时在冲突后发布。合格的示例在完成前提交状态。接受的冲突运行报告保持正式产品，不成为已提交的检查点。工作/私有快照收集保留正式输入目录、接受的产品、检查点历史和诊断证据。

### 发布和中断

一个提交独立验证成功、终止确认的运行、原生所有权、固定状态输入和正式已验收的输出库存。它从不可变的artifact目录中读取选定的输出，而不是当前的scratch。宿主持有实例锁，检查预期的HEAD，记录意图，发布一个不可变的子修订，并原子重命名HEAD。同一版本的两个运行可能完成；只有第一个不同的提交推进HEAD。一个过时的提交返回`conflict`和`automatic_retries: 0`；宿主不重新基线或重新运行它。
没有分布式CAS或对恶意操作者修改私有宿主存储的保证。

失败、取消、超时、未确认或未接受的尝试无法提交。回收已解决的工作不会删除已验收的输出、状态版本或输入证据。因此，状态提交可以跟随scratch收集。卸载保留读取访问，但围栏新状态的修改并启动。

如果发布停止在HEAD移动之前，之前的状况仍会被选中；孤儿提交不是一个已提交的检查点。在检查任何冲突的预发布文件后，显式重复已批准的**提交**可以完成该发布，而无需再次执行spool。如果相同的提交已经是EXPECTED的当前子节点，确认返回`already_committed: true`，而不会重写HEAD。后续的后代会产生冲突，而不是推断的回放。这属于限定提交协调，而不是自动重试未知执行。

中断的初始化会留下`checkpoints.pending`供操作员检查，并不会被静默覆盖。突发电源中断的持久性和任意文件系统损坏的恢复并未通过此资格认证。

### 新环境和限制

每个状态绑定的运行都会获得一个全新的工作空间，没有任何隐式的临时继承。要继续在新鲜加载后，必须显式检查出一个已提交的版本，使用`artifact-checkout CATALOG REVISION NEW_FILE`，将选定的发布加载到一个新的目录中，并从该保存的文件初始化其状态。新的实例将获得一个新的状态历史和操作员种子身份。这不会转移旧的批准、认证线性关系或验证跨发布迁移。业务兼容性仍由作者负责；自动更新/迁移是另一个里程碑。不需要内部临时空间或VM镜像来完成资格认证的后续延续。

状态位于`INSTANCE/checkpoints/`：不可变的`state.json`，一个原子的HEAD，现有的`catalog/revisions/`布局和提交意图。没有自动版本垃圾回收被添加。后续的保留工作必须考虑检查点父节点、选定的输入和下游引用，然后再删除存储。

[Round-boundary control](native-spool.md)可以在收尾完成后封锁新的开始和状态/kit变更。继续启动不会注入任何隐式的状态。控制生成会无效早期执行和状态-变更预览；在继续后请求新的预览。已经接受的资产和检查点审查在准入暂停或暂停期间仍然可用。

实际接受：[CLI runner](../crates/an-agent-host/tests/cli/README.md)。它包括实际的原生执行/取消，过时的竞争提交，发布后文件系统预发布失败，孤儿拒绝，显式提交确认，接受后Scratch的变更，提交前回收和一个恢复了kit基准线的新实例。不使用模型、合成执行凭证或新的宿主域名规则。`native_data_state.py`此外还资格直接和事件绑定的组合，固定旧的业务版本，过时的批准/提交拒绝，未知交付的围栏，实际取消/保留和显式延续在新的Python实例中。记录丢失情况在已知执行后通过证据注入控制，而不是任意崩溃或电源中断资格。

## 原生发布审查和独立延续 /no_trailblaze

```text
an-agent-host spool-release-diff PREVIOUS_PACKAGE CANDIDATE_PACKAGE
an-agent-host spool-release-diff INSTANCE/release CANDIDATE_PACKAGE
```

这是一个不执行的比较，展示两个独立验证的原生v1/v2包。它不会创建实例、批准、状态或更新关系。实例的`release/`目录选择其不可变的基准，而不是其编辑过的kit工作副本、当前检查点或有效授权。

### 报告所确立的内容

宿主验证了两个包的完整库存、受限代码字节、声明的哈希值、路径和schema/需求配对。未知字段、未列出的内容、更改的载体和禁止的链接拒绝检查，就像它们拒绝加载一样。检查执行不执行任何包钩子或依赖工具。

报告使用`an-native-spool-release-diff-v1`并包括：

- 精确的前一个/候选发布标识及其解析的manifest。
- 添加、删除或更改的代码路径，带有前/后哈希值。
- 对schema、名称、版本、入口和输出声明的更改。
- 前/后运行时、目标、交互、GPU、输入、可编辑、能力及依赖声明。
- 改变的列表以完整形式显示，而不是仅因为其缩小而被标记为安全。
- 当名称/版本标签匹配但精确字节不同时，显示`reused_coordinates`。

发布摘要仍为精确manifest字节的SHA-256，其代码哈希由此传递。仅格式更改可能产生不同的发布，而无需语义字段变更。不存在现有manifest或发布标识的变更。V1需求仍不存在，其隐式的kit编辑策略被明确标识。缺失的声明从不被制造为等价的v2授权。

`review_required` 表示更改后的精确身份；它不是授权策略。即使相同的包也会返回 `execution_granted: false` 和 `successor_authorized: false`。运行时支持不是执行批准或安全域行为的证明。报告不认证发布者，不解释 SemVer，不解析依赖项或建立兼容状态模式。静态比较仍可在 Linux 上可用，不声称 Linux 原生执行。

### 支持的操作路径

1. 比较旧的保留发布版本和已验证的候选版本。审查域合同、权限、依赖项和任何编辑的 kit 分别。
2. 将一个被认可的候选版本加载到一个新的目录中。现有实例、发布版本、kit、已接受的产品和检查点历史保持不变。
3. 如果 spool 的域合同允许，显式检出一个固定的旧检查点并从该文件初始化新实例。这创建了一个新的独立历史；它不是自动迁移或更新线性。
4. 预览并批准新实例和精确输入。旧实例/发布版本的批准不能授权它。接受成功输出并仅通过现有托管和预期版本检查提交状态。
5. 直到操作者选择其他方式，保留旧实例。被拒绝的接纳或失败的候选运行不会切换其发布版本或检查点。

没有内置的就地升级、发布者权限存储、通用状态迁移或自动重试。域作者提供兼容性和迁移规则；Loom 包含这些材料。宿主拥有准入和运行时托管。未来认证的血缘关系和精确的外部依赖绑定需要单独的合同，而不是将此报告视为更新证书。

### 资格认证

Rust 单元测试覆盖了精确身份、仅格式差异、遗留要求、不支持的请求以及字节/模式完整性拒绝。真实 macOS 命令行套件 `tests/cli/native_release.py` 审查相同标签的版本变更，拒绝在加载前添加额外能力/依赖项，拒绝跨实例批准，显式种子独立状态，拒绝失败候选者的部分输出，并继续原实例以其先前批准。这不是一个通用的迁移或电源关闭恢复测试。证据被私有保留；没有代理/模型、新后端或领域规则被添加到宿主中。

## 明确检查点 artifact 依赖关系

```text
an-agent-host spool-state-dependencies INSTANCE REVISION REQUEST_JSON [--approve DIGEST]
```

可选请求使用schema `an-native-checkpoint-dependencies-v1` 和一个`artifacts`数组，包含1到16个条目。每个条目命名一个生产者`instance`路径，`run`，声明为`output`且精确接受`revision`。例如：

```json
{"schema":"an-native-checkpoint-dependencies-v1","artifacts":[
  {"instance":"./producer","run":"build","output":"report.txt","revision":"<full digest>"}
]}
```

宿主预览一个绑定已提交检查点、实例/发布、激活生成和已验证接受源版本的计划。批准记录一个不可变的声明，并通过现有的参考存储获取源侧检查点针。重复条目、未接受或已退役的源、错误版本和过时批准拒绝。这仅是保留权限：它不添加运行时输入/文件授权，也不解释检查点的领域内容。

`spool-state-show` 包括依赖注册状态。生产者的现有 `spool-artifacts ... --references OUTPUT` 视图包括检查点所有者。检查点针不能通过尝试清理释放。HEAD 进展、私有工作收集、卸载和取消尝试输入释放保持不变。较旧的检查点保留其针直到明确释放。每个继任者拥有自己的依赖声明。

一个声明目录围住一个注册。缺少意图/完成或源声明拒绝选择该检查点；部分源针保留，没有自动修复或重试。在决定未来复核动作前，应先检查证据。完全记录的声明不能重写。现有无声明的检查点报告 `undeclared`，而不是依赖自由的。此可选声明不是完整的依赖普查。已确认的状态需有 spool 发布、接受输入政策和单独批准的 [覆盖率声明](native-storage.md) 才能释放其输入主张。已注册的复制输出有单独的显式删除门；检查点针阻止它。较旧的宿主不理解这些侧车；混合版本操作不被允许。

真实无头资格扩展了显式状态监督套件：接受的生产者输出、错误/重复版本拒绝、旧检查点与新 HEAD、客户端/监督者丢失、取消和私有收集。检查点针在取消尝试参考释放后仍存活；缺少注册完成阻止进一步执行。未知执行未被收集并永不重放。内部参考测试也拒绝尝试风格的释放和伪造的释放标记。

## 显式检查点退休

在初始化状态或提交新继任者时，使用 `--registered` 注册该版本的读者。已注册的父节点将读者策略传递给继任者。领域作者继续为每个检查点声明自己的依赖。一个遗留父节点可以产生一个已注册的继任者。其自身的读者历史保持遗留。

```text
spool-state-retire INSTANCE REVISION [--approve HASH]
spool-state-release INSTANCE REVISION [--approve HASH]
spool-state-show INSTANCE REVISION
```

退休首先关闭了对精确已提交修订的接纳。现有输入快照仍可使用。一个全新的开始、事件交付、监督资源的保留或暂停无法选择已关闭的版本。已知交付仍可进行检查。关闭 HEAD 使 HEAD 保持原状。针对该父节点进行的运行可完成并提交其后续版本，遵循常规的版本检查。已注册状态的显示路径标识其镜像。工作负载在其私有输入快照中接收状态字节。一个独立的 state 输出副本拥有自己的 custody。

发布需要第二批准，涵盖原始声明、其精确 pins 和已 drained 的读者库存。宿主检查每个读者的源发布和拥有执行的终止及最终发布确认。提交的 supervisor 保留请求在读者获取前需要正向 no-launch 结算。缺少确认、未解决执行、成功运行但无合格输入-释放证据或部分获取将保持 pins。遗留检查点在实例写入锁可用时可关闭接纳。其 pins 保持被保护，因为其原始读者无法枚举。

宿主持久化发布意图，写入每个源标记，然后为整个声明发出一个确认。确认标识检查点、声明和已发布的声明。源收集在删除已注册版本前验证拥有确认。中断的发布以 `release-unconfirmed` 形式可见，并且不会被重放。独立检查点的 pin 继续保护共享资源。释放 pins 保持检查点字节、资源载体和历史在位。载荷删除仍作为独立的操作员动作，受 [storage contract](native-storage.md) 规范。
